# @furnace/editor

The furnace editor: a Node-portable daemon serving a React 19 + dockview chrome, project-first — **the editor contains no engine**; it bundles the consumer's `@furnace/core` + extensions.

**Canonical as-built architecture: `docs/reference/editor-architecture.md`.** Chronological slice seals: `docs/learnings/seal-log.md`. This README carries the package's current-state summary; when a slice seals, update HERE (and the reference docs) — never AGENTS.md.

## Dogfood

`bun run edit` in `packages/hello-world` or `packages/dungeon` (or `bun run dungeon:editor` from the repo root).

## Architecture in one breath

- **Daemon** (Node-portable — no `Bun.*` in `src/`, enforced by `tests/no-bun-leakage.test.ts`): serves the chrome same-origin; a zod-validated command registry over `POST /api/<command>`; a mutable document session (open/save, transactional registry-validated mutations, snapshot undo/redo — await-races guarded: stale `onFileChanged` callbacks drop, a superseded `apply` throws `no-session`); an SSE change feed (`GET /api/events`); scene-file watching with conflict semantics; chrome-miss GETs mapped onto the project root (scene-doc asset sidecars resolve same-origin; dotfiles/`node_modules` refused).
- **Project-first bundling**: a browser engine bundle exporting `createViewportHost` + `createPreviewHost` + `createFieldHost` + the consumer's **`extensions` namespace** (the generator seam), and a node registry bundle for daemon-side validation + consumer `bake()` resolution — invalidated by the extensions-dir watch, which also emits `bundle-outdated` SSE so the browser reloads on source change. The chrome never value-imports engine code (machine-enforced: `tests/frontend-no-engine-leakage.test.ts`).
- **Viewport**: GPU-id picking, AABB selection highlight, translate gizmo, orbit/pan/zoom, a reflection-driven editable inspector + multi-select + `scene.batch`; camera-less FRAGMENT docs open via `loadScene` fragment mode + bounds-framed orbit.
- **Generation cockpit**: an HDR preview host (`bloom→tonemap` + headlamp + orbit; **fog is a viewport VIEW-FLAG, default off**; both canvases stay laid out — visibility swap, never `display:none`); the **World panel** (3.3 W3 — was the Generation panel; panel id `generation` persists in layouts) + ephemeral App-owned session; generation runs in a module Web Worker (runId-disciplined protocol; **cancel = terminate + lazy respawn, instant mid-run**; the worker is never respawned alone on `bundle-outdated` — a page reload refreshes worker + main thread together). The panel ASSEMBLES a world draft (attach-on-add tree, `world-draft.ts` — connectors own doors; per-region reroll; leaf-only remove; full-spec preview snapshot), drives the WORLD flow (`runWorld`/`bakeWorld` on the worker; deterministic — one call, one payload), and can retarget `worlds/index.json` at bake ("make this the game's world" — a second cleanDir-free upload); `generation.bake` writes browser-uploaded file sets root-contained (optional `cleanDir`), emitting `generation-baked` SSE.
- **Field authoring (One Field F1+F2a+F2b+F3a+F3b)**: the **Field panel** + `FieldHost` (a PreviewHost-class host) — the field tool system over a `@furnace/core/field` chunked voxel world (per-cell material classes from the project's `catalog/materials.json`, setup-loud parsed, Load gated on catalog settle). Brush chassis dig/fill/paint/smooth with masks + hollow fill (kit fills lattice-snapped, filled translucent ghost), material swatches + Alt-eyedropper + momentary shortcuts, selection tools (box with live preview, material/void floods, amber overlay, Reselect), staged hall/maze **stamps** (SchemaForm params + quarter-turn rotation + per-wall door offsets, size defaults derived from the active selection, visible seed + re-roll, hologram ghost via worker scratch-preview, lattice nudge, Enter/Esc, one-⌘Z commits recorded as generator entities), **smart objects (F3a)**: entities-list rows Open a reconfigure session (Apply = in-place splice replay, drift report list with click-to-frame, one ⌘Z restores), Freeze/Bake verbs (bake confirms; severs the recipe), footprint-accurate entity highlight, op-cost meter line + load-time compaction, `FieldHost.undo()/redo()` as the field history seam, layers + slice view (remesh clip, slice-coherent targeting), fly camera, flat-shaded/headlamp shading, background remesh+skin in a dedicated engine-direct worker (~0.7 ms/16³ on the M1). **Scatter authoring + placed props (F3b, sealed 2026-07-25)**: a second project→editor catalog contract (`catalog/entities.json`, DATA only, parsed setup-loud) SEEDS scatter params and turns `archetypeId` into a picker — it never gates (absent file → schema defaults + nominal proxies); placement ghosts draw as one merged oriented-wireframe batch, committed props as per-archetype instanced proxy primitives under a `props` layer, entities-list rows gain a prop line (`scatter · seed 3 · 1 ops · rock · 24 placed`), and the editor refuses a zero-prop scatter for PROP generators only (carvers keep core's wording). **Two tools of the editor's own (F3b)**: the **void cast** X-ray (`voidCast` — meshes the field's negative space from a one-job snapshot, dim cyan at depth-always, 512-chunk budget, dropped-and-announced by the next edit) and the **segment brush** (two-click swept capsule through core's `capsule` `BrushShape` — dig a tunnel, fill a rampart; one op, one ⌘Z). Field-first default layout (Field + Inspect; View▸Panels re-adds the rest). Saves/bakes ride `generation.bake`, loading via `field.load`; world name never prefilled. All three hosts defer init to the first nonzero canvas measure (`lib/init-when-sized.ts`). As-built: `editor-architecture.md` §15–18; deferred gate UX sets (batched for a dedicated UX/polish stage after the feature phases): `docs/backlog/editor-and-tooling/field-f2b-gate-ux-findings.md` + `field-f3a-gate-ux-findings.md` + `field-f3b-gate-ux-findings.md`.
- **The walkability advisor (One Field F4, landed 2026-07-26)**: the editor's third worker, and the Field panel's second. `analyzer-worker.ts` holds a MIRROR of the field store (synced at the same density choke point every edit passes through, buffers copied not transferred) and runs core's stage-1 walkability passes over the chunks an edit could have changed the answer for — the 26-neighbour halo plus every allocated chunk below it in the cardinal XZ columns, because stage 1's upward scans are uncapped. The whole-world connectivity passes (reachability demotion + pit detection) ride a 500 ms idle tail. Findings draw as instanced severity-coloured markers under a new `flags` layer and list in a **Flags panel section** (proximity-clustered rows, candidate/info/unreachable filters gating BOTH surfaces, click-to-frame, verdict badges). **Verify** is stage 2: the worker imports the project's own `/engine.js` and drives the consumer's real mover at one finding under an 8 s budget — the editor stays project-first (the verdict type is a structural twin of the dungeon's, never an import). Advisory throughout — nothing blocks a verb, mutates a field, or is auto-fixed; a filter hides and a demotion tags, neither deletes. Riders: a third catalog contract (`catalog/agent.json` → `setAgentProfile`; absent = advisor stays off, said once at the first edit), the collider `anchor` honoured in proxy pose via core's `collisionCenter`, `GeneratorDef.emits` replacing the `placesArchetypes` schema sniff, and a 60 m cap on the segment brush. **Known harness limit, stated because the next person to touch the marker layer needs it:** nothing in `bun test` proves the markers are DRAWN — the pixel evidence is a committed, re-runnable headless-Chrome recipe, `scripts/analyzer-pixel-check.md`. As-built: `editor-architecture.md` §19.
- The consumer-side scene loader instantiates the full built-in set from data incl. physics-from-data (instantiated, NOT stepped).
