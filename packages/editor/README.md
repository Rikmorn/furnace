# @furnace/editor

The furnace editor: a Node-portable daemon serving a React 19 **overlay-cockpit** chrome, project-first — **the editor contains no engine**; it bundles the consumer's `@furnace/core` + extensions. **Field-only since F4.5a**: one full-window canvas with floating palettes over it, and the dungeon is its sole consumer.

**Canonical as-built architecture: `docs/reference/editor-architecture.md`.** Chronological slice seals: `docs/learnings/seals/`. This README carries the package's current-state summary; when a slice seals, update HERE (and the reference docs) — never AGENTS.md.

## Dogfood

`bun run edit` in `packages/hello-world` or `packages/dungeon` (or `bun run dungeon:editor` from the repo root).

## Architecture in one breath

- **Daemon** (Node-portable — no `Bun.*` in `src/`, enforced by `tests/no-bun-leakage.test.ts`): serves the chrome same-origin; a zod-validated command registry over `POST /api/<command>` — **13 commands, 6 SSE events, 10 error codes**; an SSE change feed (`GET /api/events`); a recursive watch on the consumer's extensions directory that emits `bundle-outdated`; chrome-miss GETs mapped onto the project root (the project's `/catalog/*` files resolve same-origin; dotfiles/`node_modules` refused). **It holds no document, no schema and no generator** — it writes the bytes the browser uploads (`generation.bake`) and reads them back (`field.load`). Its resident state, since foundations T4b, is **two tables of the same kind and no other**: the **session claim** — which SSE connection is authoring which world (`src/daemon/claims.ts`) — and the **backchannel's pending asks** — which questions are out to that connection, awaiting a `session.answer` (`src/daemon/backchannel.ts`, whose ask is typed `session-timeout` at 10 s and `no-session` the moment the connection departs, never a hang). Both are connection-scoped ephemera, the same class of thing as the subscriber set: born with a connection, dead with it, nothing durable, nothing surviving a restart. The backchannel is what lets an agent read a live editing session at all — every fact but the project root and the worlds on disk lives in the browser, so the daemon **relays** rather than reads. Its first rider is `session.state`, which answers the claimed tab's `SessionState` (`src/shared/wire.ts`) — selection, tool, gesture, camera, stats, history, plus an opaque compare-only change cursor — with a `ready` discriminant so a tab whose engine has not landed cannot be read as an empty world.
- **Project-first bundling**: ONE browser engine bundle exporting `createFieldHost`, the consumer's `getService` seam, and the consumer's **`extensions` namespace** (the generator seam) — rebuilt per `GET /engine.js`, with the extensions-dir watch emitting `bundle-outdated` SSE so the browser reloads on source change. (The second, node-platform registry bundle went with the daemon's scene half in T2 — there is nothing server-side left to validate.) The chrome never value-imports engine code (machine-enforced: `tests/frontend-no-engine-leakage.test.ts`).
- **The overlay cockpit (F4.5a shell + F4.5b hands + F4.5c finish)**: ONE full-window canvas whose insets are decided by two fixed-height bars and a fixed 44 px tool rail, and nothing else (D-1 — no palette, selection or resize may move them); every other surface floats over it. Init is eager and a zero canvas measure THROWS rather than waiting. **Five floating palettes** (Entities / Session / Flags / History / Messages) drag, edge-snap, roll up and hide-all (⌘\), persisted per project at **v2** behind a CLOSED id union — a v1 dock-era blob is orphaned and an F4.5a `controls` record is dropped, never migrated; front-to-back order is session-local by design. **What the editor says** is a capped toast stack over a durable 200-entry message log — errors never auto-fade, a full stack makes a message log-only rather than evicting one, and the ⚠ chip's unread count clears only while the log palette is topmost. **World management** is a modal drawer over a `world.*` daemon namespace (list with a git-tracked tri-state, make-default, delete, rename, duplicate) — save-over-tracked, delete and make-default all confirm, and rows always refetch rather than patch. **Studio shading is the default** (camera-following key light + hemisphere fill); `normals` is a debug flag; viewport AA is a context property, so the switch disposes and re-inits the host (field, op log, tool and camera survive it). **F4.5b gave it hands.** A `pointer` gesture is what a fresh host arms, and a **CPU ray pick** (pure `field-pick.ts` — props and flag markers before entity footprints, ties to the smaller volume, gizmo handles hit-tested ahead of both, terrain-occluded by one slice-coherent raycast) is the viewport's selection: no hover pre-highlight, selection is click-driven. Entity selection is ONE concept over a **bidirectional row↔viewport sync** (`subscribeEntitySelection`), and the entities palette became the layers panel. Committed stamps gained **move / delete / duplicate** — a move IS a reconfigure session with the cursor driving its region (anchored, whole 0.5 m steps, ⇧ for vertical, reachable by gizmo handle, free drag or `G` grab; nothing hits the log until the drop), delete rides new core surface `deleteGeneratorEntity` (span spliced out, chunks rewound, downstream ops replayed — one undo entry), duplicate re-commits from the record's own provenance with a fresh seed only where core's `GeneratorDef.usesSeed` says the generator reads one. Every key and menu item comes from **ONE action registry** (`lib/actions.ts` — label, enabled, chord, matcher, gate; **split at T3b2 into `src/action-registry/` data rows + the chrome's four closures**, see that bullet) read by the window dispatcher, the burger, the shortcuts overlay, the tool rail, the Bake button and the selection chip, so a binding cannot be live and undocumented; **WASD/QE fly only while the right button is held** (D-10), which is what frees the bare letters for the tool families. Properties live in a **session card** with three states over one control set (create / rest / reconfigure — the first committed edit in rest promotes it into a reconfigure carrying that edit), rendering D-25's forms vocabulary (sliders, ± steppers, segmented enums, units, one field refusal that disables the commit verb). The op log is the editor's **ONE named history** — labels derived in `field-history.ts`, a 50-entry payload per side over the true depths, and a History palette that is a STEPPER (a row click is N undos, never a seek). The advisor's findings moved to a **Flags palette** whose header leads with candidates, with viewport marker selection (size pop + `--primary` cell outline, colour untouched) resolved at publish time so a filter can hide a selection and give it back; flood selections now draw their **cells**, surface-first under a 65 536-cube cap. `FieldPanel` is deleted. **F4.5c is the finish.** What the chrome says carries a four-member severity vocabulary (`info`/`success`/`warn`/`error`) with the advisor's idle report on `warn` rather than an error toast; toasts hold their countdown while the pointer or the keyboard is in the stack (WCAG 2.2.1); the ops and analyzer chips open detail popovers; and a long-job chip names every job standing right now, with an `aria-live` twin. **⌘K opens a command palette** over the same action registry, which also carries six `view.snap*` rows — so the axis triad's undersized tips are a redundant affordance rather than the only route to a view. Tooltips are keyboard-reachable and render their action's chord FROM the registry, so a hint and its keycap cannot disagree. The three row lists (entities, flags, history) are each a `role="grid"` with ONE tab stop — ↑/↓ between rows, → into a row's verbs, ← / Esc back, ⏎ = the row's own click — over `hooks/useRovingList.tsx`, which owns the markup as well as the keys. Dismissing an overlay returns focus to the canvas **only when the gesture that opened it started there** (D-F4.5-26 / WCAG 2.4.3), with a hand-off so a chain of two surfaces still lands there. Palettes move by keyboard, re-clamp on restore and on viewport resize, and their defaults are proven non-overlapping at the floor cell. A first-run hint and a save-as overwrite cue state the rule before the commit rather than after it, and the segment brush reads its length against the 60 m cap while you aim. Two invariants are machine-held rather than argued in prose: **ONE control library** — `components/ui/` is the only place a raw checkbox, radio or `<select>` may be written, enforced at authoring time by a Biome GritQL plugin over four allowlisted native selects — and the **D-23 token finish**, whose contrast floors are pinned by a test instead of eyeballed.
