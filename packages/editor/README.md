# @furnace/editor

The furnace editor: a Node-portable daemon serving a React 19 **overlay-cockpit** chrome, project-first — **the editor contains no engine**; it bundles the consumer's `@furnace/core` + extensions. **Field-only since F4.5a**: one full-window canvas with floating palettes over it, and the dungeon is its sole consumer.

**Canonical as-built architecture: `docs/reference/editor-architecture.md`.** Chronological slice seals: `docs/learnings/seals/`. This README carries the package's current-state summary; when a slice seals, update HERE (and the reference docs) — never AGENTS.md.

## Dogfood

`bun run edit` in `packages/hello-world` or `packages/dungeon` (or `bun run dungeon:editor` from the repo root).

### Pointing an agent at it (foundations T4b + T4c)

The daemon prints two URLs at startup — the chrome's, and the agent door's:

```
furnace editor daemon serving /path/to/project
  http://127.0.0.1:4500/
  mcp  http://127.0.0.1:4500/mcp
```

Register the second with an MCP client — for Claude Code:

```
claude mcp add --transport http furnace http://127.0.0.1:4500/mcp
```

**Nine tools appear**, prefixed by whatever key you typed (`furnace`) — **the client namespaces them**, which is why the names carry no prefix of their own. Five read: `session_state` (what the live tab holds — world, selection, what is armed, camera, stats, history, plus a compare-only change cursor), `world_list`, `project_get`, `session_query` (five questions on one `about` — the entity list with its footprints, one entity in full, the generator registry with every param schema and default, a ray probe, and the selection's replayable spec, plus the placed-prop overlap/floating lint) and `viewport_capture` (a PNG image block: the live viewport's own composition, lights and overlays, at a chosen pose). Four write: `edit_apply` (a batch of typed brush ops), `generate` (commit a generator — hall, maze, cave, scatter), `action_run` (37 of the editor's 39 named verbs, save and bake included — `edit.undo` and `edit.redo` are fenced, see below) and `session_interrupt` (one Esc). Read the port off the banner if the daemon was started with `--port 0`.

**It reads AND writes, and the boundary is the claim rather than the verb set.** An MCP client is a **guest**: it works through whichever editor tab holds the claim and can never claim, steal or release one — those three verbs take a connection token minted *into* an SSE stream this door does not hold, so they are unspellable rather than merely unadvertised. With no editor open, or with several claimed, every call says so in a sentence rather than guessing; a tab that goes quiet earns a typed `session-timeout` (10 s for most asks, 30 s for a capture or a generate). Two agents can work through one claim at once.

Four things worth knowing before pointing an agent at a world you care about:

- **A batch is one ⌘Z.** `edit_apply` validates the whole list before writing anything and lands it as ONE undo entry, so an agent's stroke is one undo for you. **Undo itself is fenced** — `edit.undo` and `edit.redo` are refused at the door, because without op attribution an agent's undo pops whatever is on top, routinely your own last stroke.
- **A refused agent call is silent on your screen** — deliberately, so an agent's business does not interrupt you. What you see is the status bar's `agent <verb> <n>` chip, which says a verb ran and which one, and *not* whether it worked.
- **Ask, don't squint.** `session_query` answers contact and interpenetration geometrically. An agent should never read a capture to decide whether a prop is resting on the floor.
- **The tools take a claimed session, not a project path.** Open the editor on the world first.

## Architecture in one breath

- **Daemon** (Node-portable — no `Bun.*` in `src/`, enforced by `tests/no-bun-leakage.test.ts`): serves the chrome same-origin; a zod-validated command registry over `POST /api/<command>` — **19 commands, 6 SSE events, 10 error codes** (T4c added six commands and neither an event nor a code); an SSE change feed (`GET /api/events`); a recursive watch on the consumer's extensions directory that emits `bundle-outdated`; chrome-miss GETs mapped onto the project root (the project's `/catalog/*` files resolve same-origin; dotfiles/`node_modules` refused). **It holds no document, no schema and no generator** — it writes the bytes the browser uploads (`generation.bake`) and reads them back (`field.load`). Its resident state, since foundations T4b, is **two tables of the same kind and no other**: the **session claim** — which SSE connection is authoring which world (`src/daemon/claims.ts`) — and the **backchannel's pending asks** — which questions are out to that connection, awaiting a `session.answer` (`src/daemon/backchannel.ts`, whose ask is typed `session-timeout` at 10 s and `no-session` the moment the connection departs, never a hang). Both are connection-scoped ephemera, the same class of thing as the subscriber set: born with a connection, dead with it, nothing durable, nothing surviving a restart. The backchannel is what lets an agent read a live editing session at all — every fact but the project root and the worlds on disk lives in the browser, so the daemon **relays** rather than reads. Its first rider was `session.state`, which answers the claimed tab's `SessionState` (`src/shared/wire.ts`) — selection, **`armed`** (what LMB does right now, a discriminated union), **`brush`** (the dormant brush SETTING, true whether or not the brush is armed), camera, stats, history, plus an opaque compare-only change cursor — with a `ready` discriminant so a tab whose engine has not landed cannot be read as an empty world. *(Those two members were `tool` and `gesture` until T4c: both were truthful and the RULE for joining them lived in a chrome hook the agent could not see, so an agent at the T4b gate walk reported "dig armed" over a screen with nothing armed. See the T4c bullet.)* Six more riders followed at T4c — the capture, the spatial query, the three write verbs and the interrupt — all of them the same relay: one addressed frame out, one `session.answer` back.
- **Project-first bundling**: ONE browser engine bundle exporting `createFieldHost`, the consumer's `getService` seam, and the consumer's **`extensions` namespace** (the generator seam) — rebuilt per `GET /engine.js`, with the extensions-dir watch emitting `bundle-outdated` SSE so the browser reloads on source change. (The second, node-platform registry bundle went with the daemon's scene half in T2 — there is nothing server-side left to validate.) The chrome never value-imports engine code (machine-enforced: `tests/frontend-no-engine-leakage.test.ts`).
- **The overlay cockpit (F4.5a shell + F4.5b hands + F4.5c finish)**: ONE full-window canvas whose insets are decided by two fixed-height bars and a fixed 44 px tool rail, and nothing else (D-1 — no palette, selection or resize may move them); every other surface floats over it. Init is eager and a zero canvas measure THROWS rather than waiting. **Five floating palettes** (Entities / Session / Flags / History / Messages) drag, edge-snap, roll up and hide-all (⌘\), persisted per project at **v2** behind a CLOSED id union — a v1 dock-era blob is orphaned and an F4.5a `controls` record is dropped, never migrated; front-to-back order is session-local by design. **What the editor says** is a capped toast stack over a durable 200-entry message log — errors never auto-fade, a full stack makes a message log-only rather than evicting one, and the ⚠ chip's unread count clears only while the log palette is topmost. **World management** is a modal drawer over a `world.*` daemon namespace (list with a git-tracked tri-state, make-default, delete, rename, duplicate) — save-over-tracked, delete and make-default all confirm, and rows always refetch rather than patch. **Studio shading is the default** (camera-following key light + hemisphere fill); `normals` is a debug flag; viewport AA had a switch here, and **foundations T4c removed MSAA from the editor entirely** — the context is `sampleCount: 1`, full stop, which is what lets an offscreen capture draw the viewport's own pipelines (`frame.renderToTexture` refuses any other count). The dispose-and-re-init round trip that switch drove stays contractual and tested; nothing in the chrome performs one on demand. **F4.5b gave it hands.** A `pointer` gesture is what a fresh host arms, and a **CPU ray pick** (pure `field-pick.ts` — props and flag markers before entity footprints, ties to the smaller volume, gizmo handles hit-tested ahead of both, terrain-occluded by one slice-coherent raycast) is the viewport's selection: no hover pre-highlight, selection is click-driven. Entity selection is ONE concept over a **bidirectional row↔viewport sync** (`subscribeEntitySelection`), and the entities palette became the layers panel. Committed stamps gained **move / delete / duplicate** — a move IS a reconfigure session with the cursor driving its region (anchored, whole 0.5 m steps, ⇧ for vertical, reachable by gizmo handle, free drag or `G` grab; nothing hits the log until the drop), delete rides new core surface `deleteGeneratorEntity` (span spliced out, chunks rewound, downstream ops replayed — one undo entry), duplicate re-commits from the record's own provenance with a fresh seed only where core's `GeneratorDef.usesSeed` says the generator reads one. Every key and menu item comes from **ONE action registry** (`lib/actions.ts` — label, enabled, chord, matcher, gate; **split at T3b2 into `src/action-registry/` data rows + the chrome's four closures**, see that bullet) read by the window dispatcher, the burger, the shortcuts overlay, the tool rail, the Bake button and the selection chip, so a binding cannot be live and undocumented; **WASD/QE fly only while the right button is held** (D-10), which is what frees the bare letters for the tool families. Properties live in a **session card** with three states over one control set (create / rest / reconfigure — the first committed edit in rest promotes it into a reconfigure carrying that edit), rendering D-25's forms vocabulary (sliders, ± steppers, segmented enums, units, one field refusal that disables the commit verb). The op log is the editor's **ONE named history** — labels derived in `field-history.ts`, a 50-entry payload per side over the true depths, and a History palette that is a STEPPER (a row click is N undos, never a seek). The advisor's findings moved to a **Flags palette** whose header leads with candidates, with viewport marker selection (size pop + `--primary` cell outline, colour untouched) resolved at publish time so a filter can hide a selection and give it back; flood selections now draw their **cells**, surface-first under a 65 536-cube cap. `FieldPanel` is deleted. **F4.5c is the finish.** What the chrome says carries a four-member severity vocabulary (`info`/`success`/`warn`/`error`) with the advisor's idle report on `warn` rather than an error toast; toasts hold their countdown while the pointer or the keyboard is in the stack (WCAG 2.2.1); the ops and analyzer chips open detail popovers; and a long-job chip names every job standing right now, with an `aria-live` twin. **⌘K opens a command palette** over the same action registry, which also carries six `view.snap*` rows — so the axis triad's undersized tips are a redundant affordance rather than the only route to a view. Tooltips are keyboard-reachable and render their action's chord FROM the registry, so a hint and its keycap cannot disagree. The three row lists (entities, flags, history) are each a `role="grid"` with ONE tab stop — ↑/↓ between rows, → into a row's verbs, ← / Esc back, ⏎ = the row's own click — over `hooks/useRovingList.tsx`, which owns the markup as well as the keys. Dismissing an overlay returns focus to the canvas **only when the gesture that opened it started there** (D-F4.5-26 / WCAG 2.4.3), with a hand-off so a chain of two surfaces still lands there. Palettes move by keyboard, re-clamp on restore and on viewport resize, and their defaults are proven non-overlapping at the floor cell. A first-run hint and a save-as overwrite cue state the rule before the commit rather than after it, and the segment brush reads its length against the 60 m cap while you aim. Two invariants are machine-held rather than argued in prose: **ONE control library** — `components/ui/` is the only place a raw checkbox, radio or `<select>` may be written, enforced at authoring time by a Biome GritQL plugin over four allowlisted native selects — and the **D-23 token finish**, whose contrast floors are pinned by a test instead of eyeballed. The stage's holistic gate PASSED (user, Safari, 2026-08-02 — new world → sculpt → stamp → props → flags → save-as → make default → bake → **walked in the game**), and its six rulings landed in one fix round: resizable palettes, one label column, burger submenus + `?`, lucide row verbs, `view.frameWorld`, and a neutral `--ring` (focus ≠ selection by rule). **A palette is now the user's to size** — a corner handle and the arrow keys, the size joining the persisted workspace blob, a declared extent becoming a DEFAULT rather than a ceiling, and exactly one home for that extent so a palette body can no longer cap its own list.
