# @furnace/editor

The furnace editor: a Node-portable daemon serving a React 19 **overlay-cockpit** chrome, project-first — **the editor contains no engine**; it bundles the consumer's `@furnace/core` + extensions. **Field-only since F4.5a**: one full-window canvas with floating palettes over it, and the dungeon is its sole consumer.

**Canonical as-built architecture: `docs/reference/editor-architecture.md`.** Chronological slice seals: `docs/learnings/seals/`. This README carries the package's current-state summary; when a slice seals, update HERE (and the reference docs) — never AGENTS.md.

## Dogfood

`bun run edit` in `packages/hello-world` or `packages/dungeon` (or `bun run dungeon:editor` from the repo root).

## Architecture in one breath

- **Daemon** (Node-portable — no `Bun.*` in `src/`, enforced by `tests/no-bun-leakage.test.ts`): serves the chrome same-origin; a zod-validated command registry over `POST /api/<command>` — **8 commands, 3 SSE events, 7 error codes**; an SSE change feed (`GET /api/events`); a recursive watch on the consumer's extensions directory that emits `bundle-outdated`; chrome-miss GETs mapped onto the project root (the project's `/catalog/*` files resolve same-origin; dotfiles/`node_modules` refused). **It holds no document, no schema and no generator** — it writes the bytes the browser uploads (`generation.bake`) and reads them back (`field.load`).
- **Project-first bundling**: ONE browser engine bundle exporting `createFieldHost`, the consumer's `getService` seam, and the consumer's **`extensions` namespace** (the generator seam) — rebuilt per `GET /engine.js`, with the extensions-dir watch emitting `bundle-outdated` SSE so the browser reloads on source change. (The second, node-platform registry bundle went with the daemon's scene half in T2 — there is nothing server-side left to validate.) The chrome never value-imports engine code (machine-enforced: `tests/frontend-no-engine-leakage.test.ts`).
- **The overlay cockpit (F4.5a shell + F4.5b hands + F4.5c finish)**: ONE full-window canvas whose insets are decided by two fixed-height bars and a fixed 44 px tool rail, and nothing else (D-1 — no palette, selection or resize may move them); every other surface floats over it. Init is eager and a zero canvas measure THROWS rather than waiting. **Five floating palettes** (Entities / Session / Flags / History / Messages) drag, edge-snap, roll up and hide-all (⌘\), persisted per project at **v2** behind a CLOSED id union — a v1 dock-era blob is orphaned and an F4.5a `controls` record is dropped, never migrated; front-to-back order is session-local by design. **What the editor says** is a capped toast stack over a durable 200-entry message log — errors never auto-fade, a full stack makes a message log-only rather than evicting one, and the ⚠ chip's unread count clears only while the log palette is topmost. **World management** is a modal drawer over a `world.*` daemon namespace (list with a git-tracked tri-state, make-default, delete, rename, duplicate) — save-over-tracked, delete and make-default all confirm, and rows always refetch rather than patch. **Studio shading is the default** (camera-following key light + hemisphere fill); `normals` is a debug flag; viewport AA is a context property, so the switch disposes and re-inits the host (field, op log, tool and camera survive it). **F4.5b gave it hands.** A `pointer` gesture is what a fresh host arms, and a **CPU ray pick** (pure `field-pick.ts` — props and flag markers before entity footprints, ties to the smaller volume, gizmo handles hit-tested ahead of both, terrain-occluded by one slice-coherent raycast) is the viewport's selection: no hover pre-highlight, selection is click-driven. Entity selection is ONE concept over a **bidirectional row↔viewport sync** (`subscribeEntitySelection`), and the entities palette became the layers panel. Committed stamps gained **move / delete / duplicate** — a move IS a reconfigure session with the cursor driving its region (anchored, whole 0.5 m steps, ⇧ for vertical, reachable by gizmo handle, free drag or `G` grab; nothing hits the log until the drop), delete rides new core surface `deleteGeneratorEntity` (span spliced out, chunks rewound, downstream ops replayed — one undo entry), duplicate re-commits from the record's own provenance with a fresh seed only where core's `GeneratorDef.usesSeed` says the generator reads one. Every key and menu item comes from **ONE action registry** (`lib/actions.ts` — label, enabled, chord, matcher, gate) read by the window dispatcher, the burger, the shortcuts overlay, the tool rail, the Bake button and the selection chip, so a binding cannot be live and undocumented; **WASD/QE fly only while the right button is held** (D-10), which is what frees the bare letters for the tool families. Properties live in a **session card** with three states over one control set (create / rest / reconfigure — the first committed edit in rest promotes it into a reconfigure carrying that edit), rendering D-25's forms vocabulary (sliders, ± steppers, segmented enums, units, one field refusal that disables the commit verb). The op log is the editor's **ONE named history** — labels derived in `field-history.ts`, a 50-entry payload per side over the true depths, and a History palette that is a STEPPER (a row click is N undos, never a seek). The advisor's findings moved to a **Flags palette** whose header leads with candidates, with viewport marker selection (size pop + `--primary` cell outline, colour untouched) resolved at publish time so a filter can hide a selection and give it back; flood selections now draw their **cells**, surface-first under a 65 536-cube cap. `FieldPanel` is deleted. **F4.5c is the finish.** What the chrome says carries a four-member severity vocabulary (`info`/`success`/`warn`/`error`) with the advisor's idle report on `warn` rather than an error toast; toasts hold their countdown while the pointer or the keyboard is in the stack (WCAG 2.2.1); the ops and analyzer chips open detail popovers; and a long-job chip names every job standing right now, with an `aria-live` twin. **⌘K opens a command palette** over the same action registry, which also carries six `view.snap*` rows — so the axis triad's undersized tips are a redundant affordance rather than the only route to a view. Tooltips are keyboard-reachable and render their action's chord FROM the registry, so a hint and its keycap cannot disagree. The three row lists (entities, flags, history) are each a `role="grid"` with ONE tab stop — ↑/↓ between rows, → into a row's verbs, ← / Esc back, ⏎ = the row's own click — over `hooks/useRovingList.tsx`, which owns the markup as well as the keys. Dismissing an overlay returns focus to the canvas **only when the gesture that opened it started there** (D-F4.5-26 / WCAG 2.4.3), with a hand-off so a chain of two surfaces still lands there. Palettes move by keyboard, re-clamp on restore and on viewport resize, and their defaults are proven non-overlapping at the floor cell. A first-run hint and a save-as overwrite cue state the rule before the commit rather than after it, and the segment brush reads its length against the 60 m cap while you aim. Two invariants are machine-held rather than argued in prose: **ONE control library** — `components/ui/` is the only place a raw checkbox, radio or `<select>` may be written, enforced at authoring time by a Biome GritQL plugin over four allowlisted native selects — and the **D-23 token finish**, whose contrast floors are pinned by a test instead of eyeballed. The stage's holistic gate PASSED (user, Safari, 2026-08-02 — new world → sculpt → stamp → props → flags → save-as → make default → bake → **walked in the game**), and its six rulings landed in one fix round: resizable palettes, one label column, burger submenus + `?`, lucide row verbs, `view.frameWorld`, and a neutral `--ring` (focus ≠ selection by rule). **A palette is now the user's to size** — a corner handle and the arrow keys, the size joining the persisted workspace blob, a declared extent becoming a DEFAULT rather than a ceiling, and exactly one home for that extent so a palette body can no longer cap its own list. The brush RADIUS became a two-way mirror, so the wheel and `[`/`]` move the number the strip shows. As-built: `editor-architecture.md` §16–§18; the design vocabulary all of it is written in: `DESIGN.md` §5.
- **`generation.bake`** — the browser produces the payload, the daemon only writes it (a cross-engine determinism finding: regenerating a seed under a different JS engine places pieces differently). Root-contained file sets with an optional `cleanDir`, emitting `generation-baked` SSE. It is what the shell's world verbs upload through. *(The 3.1/3.3 generation cockpit around it — the preview host, the World panel, the world draft, the generation worker — was deleted at F4.5a; the dungeon's worlds are dug in the field now, not assembled from region specs.)*
- **Field authoring (One Field F1+F2a+F2b+F3a+F3b)**: the dig loop's control stack (a **Field panel** until F4.5b dissolved it into the tool rail, the top strip, the session card and the Flags palette) + `FieldHost` — the field tool system over a `@furnace/core/field` chunked voxel world (per-cell material classes from the project's `catalog/materials.json`, setup-loud parsed, Load gated on catalog settle). Brush chassis dig/fill/paint/smooth with masks + hollow fill (kit fills lattice-snapped, filled translucent ghost), material swatches + Alt-eyedropper + momentary shortcuts, selection tools (box with live preview, material/void floods, amber overlay, Reselect), staged hall/maze **stamps** (SchemaForm params + quarter-turn rotation + per-wall door offsets, size defaults derived from the active selection, visible seed + re-roll, hologram ghost via worker scratch-preview, lattice nudge, Enter/Esc, one-⌘Z commits recorded as generator entities), **smart objects (F3a)**: entities-list rows Open a reconfigure session (Apply = in-place splice replay, drift report list with click-to-frame, one ⌘Z restores), Freeze/Bake verbs (bake confirms; severs the recipe), footprint-accurate entity highlight, op-cost meter line + load-time compaction, `FieldHost.undo()/redo()` as the field history seam, layers + slice view (remesh clip, slice-coherent targeting), fly camera, normals/studio shading, background remesh+skin in a dedicated engine-direct worker (~0.7 ms/16³ on the M1). **Scatter authoring + placed props (F3b, sealed 2026-07-25)**: a second project→editor catalog contract (`catalog/entities.json`, DATA only, parsed setup-loud) SEEDS scatter params and turns `archetypeId` into a picker — it never gates (absent file → schema defaults + nominal proxies); placement ghosts draw as one merged oriented-wireframe batch, committed props as per-archetype instanced proxy primitives under a `props` layer, entities-list rows gain a prop line (`scatter · seed 3 · 1 ops · rock · 24 placed`), and the editor refuses a zero-prop scatter for PROP generators only (carvers keep core's wording). **Two tools of the editor's own (F3b)**: the **void cast** X-ray (`voidCast` — meshes the field's negative space from a one-job snapshot, dim cyan at depth-always, 512-chunk budget, dropped-and-announced by the next edit) and the **segment brush** (two-click swept capsule through core's `capsule` `BrushShape` — dig a tunnel, fill a rampart; one op, one ⌘Z). Saves/bakes ride `generation.bake`, loading via `field.load`; world name never prefilled. As-built: `editor-architecture.md` §11–§14; deferred gate UX sets (batched for a dedicated UX/polish stage after the feature phases — F4.5a landed the SHELL portion; the specifics are still owed): `docs/backlog/editor-and-tooling/field-f2b-gate-ux-findings.md` + `field-f3a-gate-ux-findings.md` + `field-f3b-gate-ux-findings.md`.
- **The walkability advisor (One Field F4, landed 2026-07-26)**: the editor's second surviving worker (the field remesh worker is the other). `analyzer-worker.ts` holds a MIRROR of the field store (synced at the same density choke point every edit passes through, buffers copied not transferred) and runs core's stage-1 walkability passes over the chunks an edit could have changed the answer for — the 26-neighbour halo plus every allocated chunk below it in the cardinal XZ columns, because stage 1's upward scans are uncapped. The whole-world connectivity passes (reachability demotion + pit detection) ride a 500 ms idle tail. Findings draw as instanced severity-coloured markers under a new `flags` layer and list in a **Flags surface** (proximity-clustered rows, candidate/info/unreachable filters gating BOTH surfaces, click-to-frame, verdict badges — a panel section until F4.5b promoted it to a palette of its own). **Verify** is stage 2: the worker imports the project's own `/engine.js` and drives the consumer's real mover at one finding under an 8 s budget — the editor stays project-first (the verdict type is a structural twin of the dungeon's, never an import). Advisory throughout — nothing blocks a verb, mutates a field, or is auto-fixed; a filter hides and a demotion tags, neither deletes. Riders: a third catalog contract (`catalog/agent.json` → `setAgentProfile`; absent = advisor stays off, said once at the first edit), the collider `anchor` honoured in proxy pose via core's `collisionCenter`, `GeneratorDef.emits` replacing the `placesArchetypes` schema sniff, and a 60 m cap on the segment brush. **Known harness limit, stated because the next person to touch the marker layer needs it:** nothing in `bun test` proves the markers are DRAWN — the pixel evidence is a committed, re-runnable headless-Chrome recipe, `scripts/analyzer-pixel-check.md`. As-built: `editor-architecture.md` §15.
- **The host's framework primitives (foundations T3a, 2026-08-05)**: three package-internal modules beside `field-host.ts`, none of them exported from `field-host/index.ts` — they are seams between the host and the clusters being lifted out of it, not chrome surface. **`view-channel.ts`** is the multicast push seam all **thirteen** `subscribe*` seams sit on (every signature unchanged; ten push the current value on subscribe, `tool`/`toolError`/`stats` do not), and it changes exactly three observable things: slot-steal is dead, a throwing subscriber no longer severs its siblings, and — the corollary — a callback that throws on its INITIAL push is now logged and still gets a working unsubscribe. The chrome's one-subscription-point rule survives on cost and single-source-of-truth rather than on self-enforcement; `tests/chrome/host-seams-and-catalogs.test.tsx` is now its only detector. **`input-router.ts`** replaces the five-rung Esc ladder with a **capture stack**: a state acquires an entry when it goes live and releases it in the same canonical setter that clears it, and Esc cancels the most recent — **recency, not a declared priority**, which differs from the ladder in three reachable cases (pinned by `tests/field-host-escape.gpu.test.ts`). The segment brush is the pilot; T3c takes the DOM listeners and pointer capture. **`substrate.ts`** declares `HostSubstrate` — eleven members held BY VALUE, five as THUNKS because the host replaces them and a snapshot is a silent fork — declared here with no consumer on purpose, and **constructed in `createFieldHost` since T3b1**, whose void-cast extraction (`field-voidcast.ts`) is the first module handed one. Core's `logApplyGroup` (a whole gesture's ops as ONE undo entry) and `Registry.entries()` landed as the enablers for T3c and T3b. As-built: `editor-architecture.md` §20; the decomposition map it serves: `docs/reference/field-host-clusters.md`.
- **Scene documents are GONE — from the editor and from furnace.** The chrome that drove them was deleted at F4.5a; the daemon half — the `scene.*` command family, the document session, the mutation set, the Node-side registry bundle and the scene-file watching — was deleted in foundations T2, leaving 8 commands (`project.get`, `generation.bake`, `field.load`, and the five `world.*` verbs) and 3 SSE events. The same tranche deleted `@furnace/core/scene` itself, so this is not a parked capability waiting for a chrome: **there is no scene document to author.** `packages/hello-world` is the named casualty and accepts the loss — it remains the reference CONSUMER of the engine and simply has no editing surface (`bun run edit` there opens a field editor on a project with no field). The transactional `apply` design outlived its code as the donor for a future TransactionManager: `docs/learnings/2026-08-05-session-apply-transactional-pattern.md`.
