# F4.5 — the cockpit UX stage: charter brainstorm inputs (prepared 2026-07-27)

**Decision record (user, 2026-07-27, at the F4 seal).** The dedicated UX/polish stage
runs NOW, before F5 "scale", named **F4.5**. Rationale: F5's mega-world gate needs
exactly the tooling that is broken (F4's gate lost three items to machine-covered

## Fresh critique — `src/frontend`, **20/40**, dual-agent (snapshot 2026-07-27T23-31Z UTC)

Method: two isolated parallel assessments — a design review (source + live headless-Chrome
walk of ~24 states on the dungeon project) and a deterministic lane (bundled detector CLI +
in-page detector + computed-style measurement). Every P0/P1 below was re-verified against
source before recording. Cognitive load **HIGH (6 of 8 failed)**. Mode: Operate.

**Score context, so nobody reads this as a regression:** 20 is not comparable to the 31.
F3a + F3b + F4 landed between the two runs, roughly tripling the control surface, and each
tranche's gate-UX set was deliberately batched to this stage rather than fixed inline. The
number is the size of that deferred debt, measured.

**Specificity verdict:** authored where the domain is hard (staged stamp sessions, live-recipe
entities-list rows, the flags list's non-colour `●`/`○` severity channel, the echo-guarded
multi-select numeric inspector — all genuinely above category standard), stock where the
domain is easy (every checkbox, select, section header, tab strip). The token layer is
disciplined and enforced; nothing downstream of it is.

### New findings the register did NOT already hold

- **[P0] Field viewport's default shading is full-chroma normal-colour.** `field-host.ts:991`
  (`let shading: FieldHostShading = "flat"`) + `FieldPanel.tsx:251` (headlamp `useState(false)`).
  100% of the content surface saturated, under an Attention Rule capping accent at ≤10%.
  Functionally destructive twice over: `field-host.ts`'s own comment says material classes are
  indistinct in flat mode (so the swatch just picked means nothing on screen), and F4's red
  candidate markers sit on magenta and vanish. **One initialiser + one label to fix** —
  demote normal-colour to a named debug view flag ("normals") beside `void`.
- **[P0] Both verbs that overwrite the game's world fire unconfirmed.** No `openConfirm`
  anywhere in `field/FieldToolbar.tsx` or `WorldPanel.tsx`, while `FieldPanel.tsx:576` already
  routes the *per-stamp* bake through one. `lib/generation.ts:39` ships `makeDefault: true` —
  idempotent for the default-named world per its own comment, so the live hazard is
  rename-then-bake with the box still ticked, worsened by that checkbox rendering *below* the
  button that consumes it (`WorldPanel.tsx:316`): act-then-discover reading order.
- **Failures are typographically identical to successes.** `FieldPanel.tsx:308` — `setStatus`
  hard-codes `tone: "info"`, and `FieldToolbar`'s `report()` routes everything through it, so
  `save failed:` / `bake failed:` / `load failed:` render in neutral `muted-foreground`. The
  destructive-tone path added by the F3b gate (`FieldPanel.tsx:455`, `subscribeToolError`) is
  never reached by the toolbar's own failures. Sticky, too: the comment at `:303` assumes "a
  subsequent plain status resets the tone", but ordinary editing emits no status, so a refusal
  from minutes ago stays on screen.
- **`--destructive` fails the product's own committed floor.** `styles.css:44` measures
  **3.55:1 on `--card` / 3.73–3.75:1 on `--background`** (both lanes agreed independently) vs
  PRODUCT.md's "≥4.5:1". Paints every error string in the app *and* the flag list's candidate
  dot — the glyph the whole advisor triage rests on. Wants splitting: `--destructive` stays the
  button fill (white-on-red already measures 4.9:1), add `--destructive-text` ≈`oklch(0.68 0.16 25)`.
- **Four coexisting focus vocabularies**, measured over 53 probes: design-system ring (×20) ·
  Chrome UA `outline: auto 1px #99c8ff` (×18) · background tint only at **1.3:1**, below WCAG
  2.4.11's 3:1 (×4, the menubar) · **none at all** (×3 — both dockview tabs and the canvas).
  Two blues sit side by side in the layers row: the UA `#99c8ff` on 10 native checkboxes
  (13×13 px) against the palette's `#3e8ec1`.
- **Disabled state has three legibility outcomes from one vocabulary.** `opacity-50` over a
  neutral fill = 3.76:1; over the coloured primary/success fills it collapses to **2.41:1 / 2.5:1**.
  Related: disabled coloured buttons out-shout enabled neutral ones — on default load the two
  loudest objects on screen are both disabled.
- **Active-tool hierarchy is inverted, measured.** Active "Dig" reads at 5.48:1 while inactive
  "Fill" reads 10.75:1 and generator "Hall" 13.09:1. The selected state is the *faintest* text
  in the row.
- **13px is off the committed rem scale**, from `dockview-core@6.6.1`'s
  `--dv-tabs-and-actions-container-font-size`, which `styles.css` never overrides while it does
  remap ~14 sibling `--dv-*` colour vars. One line.
- **DESIGN.md §2's documented surface ramp is not the rendered one.** The doc assigns `--card`
  to "panels/toolbars/docks", but `styles.css:112` sets
  `--dv-group-view-background-color: var(--background)` — panel *bodies* render on
  `--background` and `--card` paints only the tab strip.
- **Two checkbox systems, two select systems, two tab systems.** Radix `ui/checkbox.tsx` in 2
  files vs raw `<input type="checkbox">` in 6 (incl. the entire Field panel, the default
  workspace); Radix `ui/select.tsx` in the Toolbar + 3 inspector fields vs native `<select>` in
  `BrushInspector` / `StampInspector` / `WorldPanel` / `AddRegionForm`; `InspectPanel.tsx:75-89`
  hand-rolls a tab strip from two bare buttons (no `role="tablist"`, no `aria-selected`) nested
  inside a dockview tab already labelled "Inspect". `ui/button.tsx` is verbatim shadcn including
  `shadow`/`shadow-sm`, so every button in every docked panel violates §4's Flat-Dock Rule.
  **Proposal worth deciding at charter: enforce with a Biome rule** banning raw
  `<input type="checkbox">` and `<select>` outside `components/ui/`, not with a §5 document —
  a lint rule would have caught all of this at authoring time and keeps catching it.
- **`Flags (319)` counts `summary.total`, not what survives the filters** (`FlagsSection.tsx:303`).
  14 brush clicks produced `ledge 46 · lip-near-wall 258 · low-clearance 15`, so the number the
  user stares at is dominated by filtered-out `info` findings. Reads as an indictment rather
  than a hint; `Flags · 15 candidates` with total secondary is the same data, opposite emotion.
- **Flag filters reset to defaults on every panel mount** (`FieldPanel.tsx:409-416`, deliberate
  per its own comment) — a tax paid dozens of times a session by the daily user.
- **`View ▸ Panels ▸ X` stacks instead of splitting** — `App.tsx:650` calls `addPanel` with no
  `position`, so a re-added panel becomes a tab in the active group and opening World *hides*
  Field. Compounding: `InspectPanel.tsx:120`'s empty state says "Pick an entity, or 'World' for
  scene settings", but the World row lives in `EntitiesPanel`, absent from the default layout —
  so in the shipped default, scene settings have no reachable entry point.
- **Keyboard**: ~28 tab stops before the canvas; the three `role="group"` containers implement
  no roving tabindex; no skip to the `tabIndex={0}` canvas. Zero tool hotkeys for a 12-button
  palette — `lib/keybindings.ts` defines five actions total, so every tool switch is a ~400px
  cursor round trip. Help▸Keyboard shortcuts is typed `Record<BindingAction, …>`
  (`MenuBar.tsx:51`), so it *structurally cannot* document the field's ~12 bindings.
- **⌘Z is ambiguous by design.** `field-host.ts` must `stopPropagation()` to stop one chord
  stepping both the field op log and the daemon scene document, and its comment admits F and ⌫
  still leak through; meanwhile the toolbar Undo button can never undo a dig while the field
  footer separately reports `undo 14`. Two histories, one chord, one button that lies.
- **Smaller, each verified:** hover makes secondary buttons *dimmer* (`hover:bg-secondary/80`
  fades toward the darker card behind it — no perceptible change, measured) · `slice` looks
  broken on enable (`SLICE_DEFAULT_Y = 8` parks the plane above any early dig) · four label
  casings in one 400px World panel, plus the app's only dashed border around "Add region" (a
  web-form/dropzone idiom) · "Player start" is an empty enabled `<select>` with no placeholder ·
  invalid world name shows a red border + three disabled buttons but never states the rule
  (`/^[a-z0-9][a-z0-9_-]*$/i`) · Settings leaks the fallback renderer (`post`/`msaa` as raw
  lowercase keys with a literal `null`, and every unset numeric shows `0`, so editing one commits
  a value the engine never had) · no axis triad in the Field viewport though `AxisTriad` exists
  and the field has the *fly* camera · `title` tooltips carry the real documentation (segment
  brush's 60 m cap, the void cast's whole contract) and are keyboard-unreachable.
- **Two observations NOT confirmed interactively — verify before acting.** (i) `· analyzing…`
  appeared on a fresh `0 chunks · 0 ops` world across three independent headless launches; the
  gate is `stats.analyzerPending > 0` and its comment states "Absent at 0: an idle advisor is the

## Decision record additions (user, at the critique hand-off)

- **Canvas-size stability is a hard rule.** "Having the viewport change as we select things is a
  big no no." This governs more than the tool-switch layout jump (Dig→Smooth +44px, →Box Select
  −76px, moving the layers row and canvas edge under the cursor): it also **kills the
  Inspect-as-context-surface idea** (a rail that expands on selection) that the critique itself
  had floated — same defect, different trigger. The canvas keeps a stable size; nothing about
  selection reflows it.
- **Direction: overlays on the canvas, Photoshop-model — not Blender's edge-docked regions.**
  The critique argued for edge-docked collapsible regions on an occlusion objection; the user
  overrode with Photoshop and the abundance of real estate, which substantially answers it.
  Charter should settle the Photoshop mechanics deliberately: floating-but-dockable palettes over
  a full-window canvas, collapse-to-icon-rail, saved workspace arrangements, and a
  **hide-all-palettes chord** (Photoshop's Tab) as the "see your work" escape hatch — that last
  one serves the canvas-stability rule better than any layout tuning.
  *Caveat on the critique's own supporting evidence:* it cited the scene `Viewport` panel's
  canvas `Popover` as in-repo precedent for overlays. That panel is in the legacy set below, so
  treat the precedent as weak — the pattern is worth adopting on its merits, not because that
  code does it.
- **Most existing panels are legacy and are DELETION CANDIDATES, not polish targets.** User,
  verbatim in substance: almost every panel other than the field editor + its viewport is
  "basically useless and from old work" — **explicitly including the panel titled "Viewport"**
  (the scene editor surface). This reframes a chunk of the critique: several findings filed
  against Inspect / Entities / World / Viewport may be moot, and the charter's first pass should
  be a **deletion pass, not a fix pass** (working-standards §Design: deletion before addition).
  Findings whose standing changes if those panels go: the unreachable-scene-settings entry point,
  the `View ▸ Panels` stacking behaviour, the hand-rolled Inspect/Schemas tab strip, the
  Settings-form fallback-renderer leaks, and the "same job, two answers" view-flags inconsistency.
  **Do not spend the UX stage polishing surfaces that are about to be cut.**
