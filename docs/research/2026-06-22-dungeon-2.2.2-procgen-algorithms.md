## 1. Branching caves — graph-first SDF union

**Recommendation:** build the cave as a graph `(seed) → {nodes, edges}` then realize every
node + edge as an SDF and **smooth-union** them into the existing air-positive `Field`.
This is the Deep Rock Galactic "pearls on a string" pattern — rooms as intersecting
spheres, connected through exit *nodes* by tunnels [V: DRG dev blog]. Maps 1:1 onto our
"branch end = connection point" and our "any field → render + voxel collision for free".

- **Layout:** at 2–3 branches, the topology can be hand-shaped (hub + N branch chains);
  a full Poisson-disk + MST + loop-edges layout (TinyKeep) is the generalization for later
  [V: Adonaac/TinyKeep; Bridson Poisson-disk]. DRG itself authors room *templates* and only
  the *stitching* is procedural — emergent MST is overkill at this node count [I].
- **Determinism:** split a sub-RNG stream per stage/node via `rng.derive(label)` so adding a
  tunnel doesn't re-roll later nodes ("same seed → same cave" survives edits). Any random
  draw while iterating a `Set`/`Map` must iterate in stable order or determinism silently
  breaks.

### New field primitives to add

**Capsule / segment SDF** (tunnel between two points) — we only have axis-aligned `shaft`:
```ts
// air-positive: >0 inside the tube, <0 outside (matches our Field convention)
function capsuleCavern(ax,ay,az, bx,by,bz, r): Field {
  return (x, y, z) => {
    const pax=x-ax, pay=y-ay, paz=z-az;
    const bax=bx-ax, bay=by-ay, baz=bz-az;
    const baLen2 = bax*bax + bay*bay + baz*baz;
    const h = Math.min(1, Math.max(0, (pax*bax + pay*bay + paz*baz) / baLen2));
    const dx=pax-bax*h, dy=pay-bay*h, dz=paz-baz*h;
    return r - Math.hypot(dx, dy, dz); // IQ sdCapsule, sign-flipped
  };
}
```

**Smooth-union (smax)** — air-positive analogue of IQ `opSmoothUnion` (our `union = max`,
verified `field.ts:51`). Replaces hard `union` so chambers/tunnels fuse without a crease:
```ts
function smax(a, b, k) {            // k in distance units = max blend thickening
  const kk = k * 4;
  const h = Math.max(kk - Math.abs(a - b), 0);
  return Math.max(a, b) + (h * h * 0.25) / kk;
}
function smoothUnion(k, ...fields) { /* fold smax over fields; drop-in for union() */ }
```
**Gotcha:** `k` must be **≥ ~1 cellSize (≥ 0.5 m)** or the fillet is sub-grid and degrades
back to hard union (crease in field + bevel in mesh + sub-cell slivers). Naive Surface Nets
bevels hard creases anyway (only Dual Contouring keeps sharp edges) — smooth-union is what
the mesher is happiest with and it *reduces* the sub-cell voxel pockets that cause capsule
wedging [V: 0fps, Frisken; I].

### Scale, perf, walkable floors
- A 30–60 m branching cave is **nowhere near** a browser-wasm limit. Field memory is
  negligible (~0.6–2 MB); shell-only voxels scale with **surface area**, ~10⁴–10⁵ voxels.
  Bound the union's sample domain to the region AABB; 32³–64³ cells/region is the universal
  norm; SVO/LOD are over-engineering at this scale [V: zeux, bonsairobo, GPU Gems 3].
- **Walkable floors:** anchor the floor with a monotone vertical term, add noise *on top*
  (never pure noise); force strongly-solid below a hard-floor line; **taper noise amplitude
  to ~0 at floor height** — extend our existing `taperedNoiseDisplace` + `rectWeight` to
  taper by **Y** too; cap peak-to-peak floor variation ≤ ~0.3 m (< `STEP_HEIGHT 0.4`); keep
  anisotropic-Y `0.25` [V: GPU Gems 3 Ch.1; our AGENTS.md].
- **Nyquist:** features thinner than ~1 cell (1.0 m) vanish/alias — keep tunnel radius
  ≥ ~1 m, walls ≥ ~1.5–2 m. Overlap tunnel capsules *into* chambers (extend endpoint past
  node center) + smooth-union, or branches disconnect.

## 2. Architectural rooms — one constructive box builder

**Recommendation:** a single private `boxRoom(rng, params) → RegionData`. **No BSP, no WFC,
no shape grammars, no tile kit** — all are overkill for two seeded single-room generators
(verdicts below). `pillarHall` and `greatHall` are thin wrappers passing different param
ranges + a feature pass. The hard part (exact, ghost-free collision) is already solved by
box+cuboid; this is the lightest PCG category (constructive: lay features directly).

- **Wall-with-doorway → boxes:** never subtract; emit the wall as the boxes *around* the
  opening — two side segments + a **lintel** box above the door (the lintel is what makes a
  doorway read as a doorway). Mesh box ≡ collider cuboid (1:1, exact). Wall thickness is its
  own param so `width`/`depth` always mean *interior* clearance [V: Brogue, Spelunky
  constructive assembly].
- **Pillars:** regular grid → bounded jitter (**≤ 15 % of bay**, beyond which it reads as
  rubble) → **keep-out cull** any pillar inside the doorway→interior walk corridor
  (footprint = pillar r + capsule r 0.3 + clearance). Discrete bay spacing via `rng.pick`
  reads as intentional; widen the central nave aligned to the doorway (hypostyle/Vitruvian
  "eustyle": center bay ≈ 1.33× side bays) [V: Karnak hypostyle, Vitruvius intercolumniation].
- **greatHall platform/step:** dais top at `h_plat`. If `h_plat ≤ 0.4`, step straight up; if
  `> 0.4` you **must** provide a step-stack (each rise `= h_plat/N` clamped **≤ 0.4 − ε**,
  tread depth ≥ 1.0 m) — **prefer steps over ramps** (ramps aren't axis-aligned cuboids).
  Derive step count from height; never hardcode.
- **Cheap anti-shoebox wins (all additive boxes):** wall niches/alcoves, lintels/beams over
  pillars, coffered ceiling, raised platform+steps, off-center doorway + widened nave.
- **Variety that reads as designed:** continuous params get *narrow* ranges; style decisions
  are *discrete* `rng.pick`s (the Spelunky "templates + bounded mutation" lesson).
- **Overkill verdict:** BSP solves partitioning-one-area-into-many-rooms (we make one room);
  WFC solves tile-adjacency for an *art kit* (we have none — revisit if we build a backrooms
  modular kit); CGA grammars solve façade hierarchies (our `emitWall` split is a one-level
  rule); template kits earn their place only with handcrafted art. Steal only the *split-rule*
  concept + *discrete-pick-for-style* [V: source domains for each].

| | pillarHall | greatHall |
|---|---|---|
| width × depth | 8–14 × 10–18 m | 14–22 × 18–30 m |
| height | 3.5–5 m | 6–9 m (tall) |
| pillars | grid, bay 3–4.5 m, jittered, culled | none/sparse |
| platform | — | dais +0.3–0.8 m + derived step-stack |

## 3. Connections & seams — connection-point contract + **vestibule** (the design change)

**Recommendation (changes our earlier "overlap-coverage" plan):** use a connection-point
(socket) contract, **cardinal-snap room facings** (keep rooms axis-aligned for cheap cuboid
colliders), and for the actual cave↔room seam insert a short deterministic **vestibule
connector region** — do **NOT** directly overlap the voxel cave collider with the cuboid
room collider.

### Connection contract
```ts
type Connection = {
  position: Vec3;   // opening center, ON the floor plane (makes floor-height check arithmetic)
  facing:   Vec3;   // OUTWARD unit normal (points away from interior); join = facings negate
  width:    number; // clear opening; need ≥ 2·capsuleRadius + margin (≥ 0.7 m)
  height:   number; // clear opening; need ≥ capsule total height
  kind:     "door" | "tunnel-mouth"; // compatibility tag; near-trivial now, needed at type #2
};
```
Derive any transform from `position`+`facing` (single source of truth — no separate
quaternion). `facing` outward + match-by-negation kills the mirror-flip ambiguity
[V: Dungeon Architect outward-arrow alignment; Brogue door-faces-dungeon].

### Cardinal-snap alignment
Snap the cave branch facing to the nearest cardinal `{±X, ±Z}`; the room's required yaw is
one of 4 (room stays axis-aligned → cuboid + voxel grid stay world-aligned, no diagonal
staircase). Place the room by computing its `origin` **from** the required doorway world
position (`origin = P_cave − R·P_door`), not by placing then hoping the door lines up. Free
yaw is rejected: it forces OBB room colliders the controller + voxel grid don't want.

### The vestibule (seam continuity) — and why NOT direct overlap
**Verdict: overlapping a `voxels` collider with a `cuboid` collider is the high-risk geometry
that produces our gate-only wedge/stall/invisible-wall bugs.** Mechanism: the custom
collide-and-slide caster gets **two contact normals at once** from two unrelated surfaces at
slightly different heights (voxel floor quantized 0.25/0.5 m; cuboid floor flat) → resolving
one re-penetrates the other → wedge. Same class as the internal-edge ghost collisions we left
behind, but now from two colliders disagreeing [I, from controller design + 2.2.1 gate
write-ups; consistent with Rapier offset-margin docs].

The **vestibule** splits the one scary heterogeneous seam into two *individually-proven
homogeneous* seams:
- vestibule ↔ room = flat **cuboid↔cuboid butt-join** (no internal edges, equal floor `y` by
  construction);
- vestibule ↔ cave = **voxels overlapping a flat box floor** — exactly the hall↔chamber
  overlap-coverage fix shipped + confirmed un-stuck in 2.2.1.

Set vestibule floor `y` = room doorway floor `y`; ramp the vestibule if
`|P_cave.y − P_room.y| > STEP_HEIGHT`. (Connector-at-the-seam is the dominant prior-art
pattern: Dungeon Architect connector assets, Quake portal polygons.)

**Precise rule (reconciles with 2.2.1's shipped overlap):** voxel↔cuboid overlap is safe **only in
the flat-coplanar-floor case** — the flat cuboid floor sits at/above the highest voxel top in the
footprint, so the capsule rests/slides on the flat floor and the voxels are inert backstop (this is
the chamber-voxels-over-authored-corridor-floor overlap 2.2.1 confirmed un-stuck). The wedge comes
from the *uncontrolled* case — voxels overlapping a cuboid at a height mismatch or against walls
(two contradictory contact normals). The vestibule exists to *guarantee* the safe case; never let
cave voxels overlap a room's walls or a floor at a different `y`. The authored-level↔cave entrance
is the same seam (authored floor = flat cuboid) and uses the same safe overlap.

Ranking for our voxel↔cuboid case: **vestibule** > overlap-onto-flat-floor-skirt (fallback,
fewer walls) > field-union (wrong for a box room — re-imports voxel blockiness) > explicit
mesh stitch (worst — re-imports internal-edge ghosts; only viable on an edge-aware backend
per `jolt-backend-swap.md`).

### Headless validation (convert gate-only seam bugs into asserts)
1. **Flood-fill** air from spawn over the composed grid; assert every room interior + each
   connection cell is reached; assert the floor cell under each connection is solid.
2. **Seam floor-height** arithmetic: `|caveConn.y − roomConn.y| ≤ STEP_HEIGHT` (or a ramp).
3. **Capsule walk-probe across each seam**, both directions, multiple lateral lanes, on the
   **full composed collider set** — assert it crosses, loses no >`STEP_HEIGHT` height, never
   stalls. This is the one that earns its keep (extend the 2.2.1 `traversal.gpu.test.ts`
   harness). **2.2.1 lesson:** a subset-collider or drop-in-rest probe gives false
   confidence — must walk the full set.
4. **Width/profile** assert `min(widths) ≥ 0.7 m`.
