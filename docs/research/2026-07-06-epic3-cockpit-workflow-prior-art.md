## 1. Houdini — the canonical cook/freeze/bake loop

**(a) Loop.** The network is *live*: every parameter change re-cooks upstream nodes; heavy chains get caching nodes inserted to stop re-cooks ([SideFX lock docs](https://www.sidefx.com/docs/houdini/model/lock_nodes.html); [Artivoxa on cooking](https://www.artivoxa.com/how-houdinis-procedural-approach-saves-you-hours-on-every-project/)). No built-in side-by-side candidate browsing — reroll = change a seed parameter and re-cook.

**(b/c) Curation verbs.** Houdini's answer to pin/lock is *freezing a point in the graph*: the **lock flag** "record[s] its current output and then only output[s] that geometry, instead of cooking its inputs," with the frozen geometry saved into the `.hip` file ([lock docs](https://www.sidefx.com/docs/houdini/model/lock_nodes.html)); the **Stash SOP** is the first-class version — it caches geometry, "never passes the input directly to the output," and deliberately breaks the dependency so downstream no longer depends on upstream ([Stash SOP docs](https://www.sidefx.com/docs/houdini/nodes/sop/stash.html)). Hand-edits then happen *downstream* of the frozen point — non-destructive layering, the generator recipe stays present but dormant. The one-way bake lives at the engine boundary: **Houdini Engine for Unreal** distinguishes *cooked* outputs ("owned by the Houdini Asset Actor, and will be destroyed with it") from *baked* outputs ("independent, and are not tied to the Houdini Asset that generated them"), with verbs **Recook** (force), **Rebuild** (reimport HDA + recook), **Reset Parameters**, and **Bake to Actors / Bake to Blueprint / Bake to Asset**, plus **Replace-with-baked** variants ([Details Panel docs](https://www.sidefx.com/docs/houdini/unreal/detailspanel.html); [bake commands](https://www.sidefx.com/docs/unreal16.5/_commands.html)). This cooked-vs-baked split is the closest existing precedent for a "generation cockpit → static level" pipeline.

**(d) Failure viz.** Per-node **badges**: a warning shows a badge but cooking continues; an error "prevents cooking subsequent nodes and displays a prominent badge on the node," with full text in the node info window ([badges docs](https://www.sidefx.com/docs/houdini/network/badges.html)). Failures are thus *located on the graph node that produced them*, and hard failures visibly dam the downstream network. A dedicated Error SOP exists for tool authors to raise deliberate errors ([mirrored node doc](https://houdinihelp.ru/nodes/sop/error.html) — official English page not fetched this session).

## 2. Unreal PCG — live graphs, one-way detach

**(a)** A PCG Component/Volume holds a graph; you click **Generate** in Details, and graph edits "update in real time in the Editor viewport" ([PCG overview](https://dev.epicgames.com/documentation/unreal-engine/procedural-content-generation-overview)). Determinism/reroll rides on the component **Seed** plus per-node seed modes (From Component / Seed From Position) — verified only via secondary sources ([bugnet](https://bugnet.io/blog/fix-unreal-pcg-determinism-different-results), [StraySpark](https://www.strayspark.studio/blog/ue5-pcg-production-ready-guide)).

**(b/c)** Curation is **one-way detach**: no partial pin/lock of a generated subset exists in the framework; community practice is *Clear PCG Link* then "Convert Actor to Blueprint" / "Convert *** To Static Mesh," or spawn real actors from the graph so they're movable — with the caveat that cleared results are "static and no longer procedurally controlled" ([Epic forums thread](https://forums.unrealengine.com/t/any-way-to-bake-pcg-results-so-i-can-start-manually-edit-the-placed-assets/1204104); [bake-down tutorial](https://www.youtube.com/watch?v=RnkMLt0iZhQ)). Regenerate wipes non-detached output; hand-edit therefore happens only *after* the bake. Posture: "PCG graphs are live; nothing is baked until you decide to" ([gamedevcore tutorial](https://www.gamedevcore.com/blog/ue5-pcg-tutorial-procedural-generation/)).

**(d) Failure viz — the strongest prior art here.** Per-node **Debug rendering** (checkbox or `D`) draws that node's intermediate points in the viewport; **Inspect** (`A`) opens the node's full point/attribute table; `E` toggles nodes on/off for bisection ([PCG overview](https://dev.epicgames.com/documentation/unreal-engine/procedural-content-generation-overview)). Point **density** renders as a black→white gradient on debug points ([node reference](https://dev.epicgames.com/documentation/en-us/unreal-engine/procedural-content-generation-framework-node-reference-in-unreal-engine)); a **Debug Object Tree** visualizes runtime generation grids ([runtime debugging docs](https://dev.epicgames.com/documentation/unreal-engine/pcg-runtime-generation-debugging-in-unreal-engine)). Pattern: *any node's intermediate data is spatially inspectable in-viewport, not in a log*.

## 3. Townscaper / Bad North — curation-first, failure designed away

The human owns macro-structure; the algorithm elaborates: "I want the user to feel like they're in control of the large shapes. But then I get to play around with … the small shapes" — Stålberg ([Game Developer / AI and Games analysis](https://www.gamedeveloper.com/game-platforms/how-townscaper-works-a-story-four-games-in-the-making)); "I give it a bunch of puzzle pieces and then it figures out how to create a coherent environment without any gaps" ([MCV interview](https://mcvuk.com/business-news/when-we-made-townscaper/)). Every click is an incremental generate+local-resolve; the user's placed blocks *are* the pins — there is no separate lock verb. On failure: **Bad North restarts island generation entirely on failure**, and enforced a navigability constraint between beaches and defensive positions; **Townscaper instead "is actually allowed to fail silently"** — degraded output (loose hanging structures) instead of an error ([same Game Developer piece](https://www.gamedeveloper.com/game-platforms/how-townscaper-works-a-story-four-games-in-the-making)). WFC background: on contradiction the classic options are restart, backtrack, or modify-in-blocks ([Boris the Brave, WFC Explained](https://www.boristhebrave.com/2020/04/13/wave-function-collapse-explained/); [Modifying in Blocks](https://www.boristhebrave.com/2021/10/26/model-synthesis-and-modifying-in-blocks/)); Townscaper also picks tiles by fixed priority rather than randomness so users can *reliably steer* outcomes ([Boris, Constraint-Based Tile Generators](https://www.boristhebrave.com/2021/10/31/constraint-based-tile-generators/)).

## 4. Lightweight dungeon/tile tools

**Dungeon Alchemist:** per-room theme → generate; "press the randomize button and … ever new rooms" (reroll is *per room*, other rooms untouched — the pin unit is the room); then full object-level curation: select, move, scale, rotate, add, delete ([site](https://www.dungeonalchemist.com/), [wiki Getting Started](https://dungeonalchemist.fandom.com/wiki/Getting_Started), [Objects](https://dungeonalchemist.fandom.com/wiki/Objects)); bake = export to printable image or VTT (Foundry/Roll20/FantasyGrounds) ([FAQ](https://www.dungeonalchemist.com/faqs)). No failure-viz found **[unverified — likely none]**.

**LDtk auto-layers:** rules repaint tiles live as you edit the IntGrid source ([auto-layers docs](https://ldtk.io/docs/general/auto-layers/)); hand-edit = edit the *source* layer, not the output — direct manual tiles on auto-layers were an open feature request ([issue #985](https://github.com/deepnight/ldtk/issues/985)), and whole-project rule re-application can be switched to manual for big projects ([1.2.0 devlog](https://deepnight.itch.io/ldtk/devlog/471310/ldtk-120-is-out-happy-new-year); [issue #1046](https://github.com/deepnight/ldtk/issues/1046)). `SHIFT+R` toggles rendering to reveal the underlying IntGrid — a "show the input under the output" diagnostic ([docs](https://ldtk.io/docs/general/auto-layers/)).

**Tiled automapping:** rules run on demand (**Map > AutoMap**) or continuously (**AutoMap While Drawing**, integrated into the paint undo step since 1.9); output is *plain editable tiles* written into layers — i.e., generation is bake-by-default, freely overpaintable, but re-running rules can overwrite edits unless rules account for prior output ([automapping docs](https://doc.mapeditor.org/en/stable/manual/automapping/); [Tiled 1.9 notes](http://www.mapeditor.org/2022/06/25/tiled-1-9-released.html); [eishiya tips](https://eishiya.com/articles/tiled/)).

## 5. Studio curation pipelines

**Hades:** hand-authored chambers, procedurally *sequenced* — curation happens on the pool, not the output: per-biome design principles (Tartarus walled medium chambers; small chambers early, large late) — designer Ed Gorinstein ([Kotaku](https://kotaku.com/hades-level-design-is-less-random-than-it-seems-1845254545); [Konsoll 2021 talk "Hand-Crafted Variance"](https://www.youtube.com/watch?v=qv_vUa7bxks)). **Dead Cells:** fixed hand-made world layout + hand-designed room "tiles" + a per-biome **concept graph** instructing the generator (length, special-tile counts); the generator retries rooms until they satisfy the graph ([Deepnight/Bénard](https://deepnight.net/tutorial/the-level-design-of-dead-cells-a-hybrid-approach/); [Game Developer](https://www.gamedeveloper.com/design/building-the-level-design-of-a-procedurally-generated-metroidvania-a-hybrid-approach-)). **Diablo 1** did *not* assemble vetted chunks; levels are generated per-tile on a 40×40 grid with 100+ tile variants covering every connection case ([Boris the Brave analysis](https://www.boristhebrave.com/2019/07/14/dungeon-generation-in-diablo-1/); [Brevik GDC postmortem](https://gdcvault.com/play/1023469/Classic-Game-Postmortem)). The common shape: *humans vet inputs (chunk pools + constraints); the generator's runtime output is never hand-edited.*

|---|---|---|---|---|---|

| LDtk | rules repaint live | rule randomness (seed detail **[unverified]**) | manual rule-run mode | edit IntGrid source; output override = feature request | export on save |

## Failure-visualization patterns (prior art)

1. **Error-as-graph-badge + dammed flow** (Houdini): failure pinned to the producing node, warning vs error severity, hard errors visibly stop downstream cooking ([badges](https://www.sidefx.com/docs/houdini/network/badges.html)).
2. **In-viewport intermediate-data debug** (UE PCG): any node's points drawn spatially on demand (`D`), scalar diagnostics (density) as color gradient, full attribute table on Inspect (`A`), node bisection via enable-toggle ([overview](https://dev.epicgames.com/documentation/unreal-engine/procedural-content-generation-overview)) — the direct model for visualizing *placement candidates/rejections in the scene*, not logs.
3. **Show the input under the output** (LDtk `SHIFT+R`) — toggling between generated result and source data localizes rule misfires ([docs](https://ldtk.io/docs/general/auto-layers/)).
4. **Degrade visibly instead of erroring** (Townscaper's "silent failure" leaves visibly-wrong geometry in place) vs. **restart wholesale** (Bad North) ([Game Developer](https://www.gamedeveloper.com/game-platforms/how-townscaper-works-a-story-four-games-in-the-making)); WFC literature frames the option space as restart / backtrack / re-solve locally in blocks ([Boris](https://www.boristhebrave.com/2021/10/26/model-synthesis-and-modifying-in-blocks/)).
5. **Not found:** a shipped tool that renders *constraint-violation overlays* (e.g., highlighting the exact overlapping volumes that rejected a placement) — Houdini/PCG show data and error locus, not the violated constraint itself. Treat that as an open design space **[absence-claim: based on this survey only]**.

**Takeaway for the cockpit:** the industry-consistent shape is Houdini's — live recipe + freeze-points (stash/lock = "pin region") during curation, then an explicit one-way engine bake (cooked-vs-baked distinction, PCG's detach posture confirms the same choice); reroll granularity should be the sub-region (Dungeon Alchemist's per-room randomize, Townscaper's per-click local resolve), and failure reporting should follow PCG/Houdini: spatial, per-node/per-piece, in-viewport.
