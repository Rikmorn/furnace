**Pattern definition, as precedented:** an authored world contains placed markers declaring "this bounded region expands into section-type X from vocabulary/pool T, seeded by S." Canonical instances: Minecraft's jigsaw start pieces ([minecraft.wiki/Jigsaw_structure](https://minecraft.wiki/w/Jigsaw_structure)), Unreal's PCG Volumes/Components with `GenerateAtRuntime` ([Epic docs: PCG Generation Modes](https://dev.epicgames.com/documentation/en-us/unreal-engine/using-pcg-generation-modes-in-unreal-engine)), and Warframe's tileset templates ([Warframe wiki: Tile Sets](https://wiki.warframe.com/w/Tile_Sets), [GameAIPro ch. 7, Brewer](https://www.gameaipro.com/GameAIProOnlineEdition2021/GameAIProOnlineEdition2021_Chapter07_Managing_Pacing_in_Procedural_Levels_in_Warframe.pdf)).

## (i) Section-generation algorithm families, by success guarantee

| Family | Guarantee class | Evidence |
|---|---|---|
| Perfect maze (backtracker, Wilson's, Kruskal) | **Guaranteed by construction** — output is a spanning tree of the grid graph; always exists | [Wikipedia: Maze generation](https://en.wikipedia.org/wiki/Maze_generation_algorithm), [KSU wiki: Perfect Maze Generators](https://people.cs.ksu.edu/~ashley78/wiki.ashleycoleman.me/index.php/Perfect_Maze_Generators.html) |
| BSP room split | **Guaranteed by construction** — "Thanks to the BSP tree, we can't have two overlapping rooms"; connectivity via sibling-corridor recursion | [RogueBasin (mirror): Basic BSP](https://chizaruu.github.io/roguebasin/basic_bsp_dungeon_generation) |
| Fixed-grid template fill (Spelunky: 4×4 room grid, drunken-walk path, typed templates with guaranteed exits) | **Guaranteed by construction** — every cell gets a template; path rooms guarantee L/R/drop exits; no retry mechanism exists | [Kazemi, Spelunky Generator Lessons](https://tinysubversions.com/spelunkyGen/) |
| Cellular-automata cave in bounded box | **Always emits output; connectivity NOT guaranteed** — standard fix is deterministic flood-fill post-pass (keep largest cavern / wall off the rest); some variants restart if open-area < threshold | [RogueBasin: CA caves](https://www.roguebasin.com/index.php/Cellular_Automata_Method_for_Generating_Random_Cave-Like_Levels), [Jeremy Kun: CA cave generation](https://www.jeremykun.com/2012/07/29/the-cellular-automaton-method-for-cave-generation/) |
| Jigsaw piece-chaining (Minecraft) | **Degrades, never fails** — piece-level rejection + fallback pools + truncation; global generation always terminates | [minecraft.wiki/Jigsaw_structure](https://minecraft.wiki/w/Jigsaw_structure) |
| Graph→template assembly (Dead Cells, Gungeon, Edgar) | **Search-with-retry** — Dead Cells "tries another room until it finds one" ([Deepnight](https://deepnight.net/tutorial/the-level-design-of-dead-cells-a-hybrid-approach/)); Gungeon "will backtrack and regen the choice of room, up to 3 times" ([BorisTheBrave](https://www.boristhebrave.com/2019/07/28/dungeon-generation-in-enter-the-gungeon/)); Edgar ships a timeout that stops "with an error" on too-hard inputs ([Edgar docs](https://ondrejnepozitek.github.io/Edgar-Unity/docs/generators/dungeon-generator/)) | (inline) |
| Free-space packing (DunGen) | **Can fail entirely** — "scraps the entire thing and starts over" on main-path placement failure | [DunGen Unity thread](https://discussions.unity.com/t/dungen-procedural-dungeon-generation/531207) |
| WFC | **Can fail (contradiction)** — "the algorithm has run into a contradiction and can not continue," though "surprisingly rarely"; reference impl aborts without output; underlying decision problem is NP-hard | [mxgmn/WaveFunctionCollapse README](https://github.com/mxgmn/WaveFunctionCollapse); restart-vs-backtracking tradeoff surveyed in [BorisTheBrave: WFC Explained](https://www.boristhebrave.com/2020/04/13/wave-function-collapse-explained/); Caves of Qud does not rely on WFC alone — it segments maps first and adds connectivity in follow-up passes ([Mills' notes on Bucklew's talk](https://christianjmills.com/posts/dungeon-generation-via-wavefunctioncollapse-notes/), [GDC Vault](https://gdcvault.com/play/1026263/Math-for-Game-Developers-Tile)) |

The guaranteed class is exactly the *partition-first / fill-a-cell* vocabularies (maze, BSP, fixed grid, bounded CA-plus-flood-fill); everything that *packs shapes into shared free space* is search-class. (This matches the furnace placement-arc experience — see `docs/learnings/2026-07-05-dungeon-placement-arc-postmortem.md`.)

## (ii) Precedented socket-contract fields

- **Envelope/bounds:** Minecraft `max_distance_from_center` (1–128 horizontal) defines an outer box of side `2a+1`; pieces "must not exceed the outer bounding box" and "not intersect with any other piece" ([wiki](https://minecraft.wiki/w/Jigsaw_structure)). UE scopes by volume/partition-grid cell + generation radii per grid size ([Epic docs](https://dev.epicgames.com/documentation/en-us/unreal-engine/using-pcg-generation-modes-in-unreal-engine)).
- **Connection points:** jigsaw blocks carry `name`/`target name`/target pool/selection priority/placement priority ([wiki](https://minecraft.wiki/w/Jigsaw_structure)); joint type (`rollable` vs `aligned`) is documented on the [Jigsaw Block page](https://minecraft.fandom.com/wiki/Jigsaw_Block) *(field name from general knowledge — unverified this session)*. Gungeon/Warframe use per-room predefined exits/"doors" aligned pairwise ([BorisTheBrave](https://www.boristhebrave.com/2019/07/28/dungeon-generation-in-enter-the-gungeon/), [Warframe wiki](https://wiki.warframe.com/w/Tile_Sets)).
- **Type/theme = pool ID:** `start_pool` + weighted template pools with a **fallback pool** (Minecraft); biome-specific tile libraries (Dead Cells); tileset + block-type roles Start/Connector/Intermediate/Objective/Exit (Warframe).
- **Size/depth budget:** `max_depth` 0–20 (village=6, trial chamber=20) ([wiki/Config](https://minecraft.wiki/w/Jigsaw_structure/Config)); Warframe templates carry "maximum branching depth."
- **Seed:** UE PCG components own an explicit seed property ([tutorial](https://medium.com/@sarah.hyperdense/pcg-basics-your-first-procedural-scatter-system-in-ue5-fab626e1d6f0)); DunGen syncs a seed for identical dungeons ([thread](https://discussions.unity.com/t/dungen-procedural-dungeon-generation/531207)); Minecraft *derives* the seed from world seed + chunk coordinates rather than storing it per-socket ([wiki](https://minecraft.wiki/w/Jigsaw_structure)) — a notable alternative: seed-from-placement, not seed-as-authored-field.
- **Failure policy:** fallback pools → terminator/`empty_pool_element` caps → silent truncation (Minecraft); bounded backtrack + corridor fallback (Gungeon); full restart (DunGen); timeout-with-error (Edgar).

## (iii) Determinism / versioning practices

Minecraft: reproducible from world seed + chunk coords ([wiki](https://minecraft.wiki/w/Jigsaw_structure)). UE PCG: same component seed ⇒ same output, but **only relative to a specific graph** — editing the graph changes results under the same seed ([bugnet.io](https://bugnet.io/blog/fix-unreal-pcg-determinism-different-results), secondary source — flag); Epic's runtime-gen page is **silent on determinism guarantees** (verified: the fetched page doesn't address it). No surveyed system promises cross-content-version seed stability; determinism is universally *seed × content-version* (Minecraft structures changing across game versions is general knowledge — unverified here).

## (iv) Negative space — what nobody does (absence-of-evidence from this survey, flagged as such)

1. **Nobody ships guaranteed-success free-space packing.** Every packing/search-style system carries retry/backtrack/timeout/restart machinery. The only "never fails" systems changed the *vocabulary* (fixed grid, partition-then-fill) or the *failure semantics* (jigsaw truncation).
2. **Nobody retries globally at a socket.** Jigsaw failure is resolved *locally* — next piece, fallback pool, cap, or just no piece — never by re-solving neighbors. Local degradation, not global search, is the shipped runtime posture.
3. **Nobody uses runtime UE-style PCG for structural room assembly.** Epic's runtime mode is scatter/decoration around generation sources with frame-time budgets and actor pooling; it has no fit/failure concept at all ([Epic docs](https://dev.epicgames.com/documentation/en-us/unreal-engine/using-pcg-generation-modes-in-unreal-engine)).
4. **Nobody exposes "success guarantee" as a contract field.** The guarantee lives implicitly in vocabulary choice; no surveyed schema declares it. Making it explicit in a socket contract is novel (and defensible).
5. **Nobody runs raw WFC unsupervised in production sockets** — Qud brackets it with constructive pre/post passes ([Mills](https://christianjmills.com/posts/dungeon-generation-via-wavefunctioncollapse-notes/)).

**Implication for the editor-time/runtime split:** the precedent overwhelmingly supports authored/baked *structure* + runtime sockets restricted to truncation-safe (jigsaw-style) or construction-guaranteed (maze/BSP/fixed-grid/bounded-CA-with-deterministic-flood-fill) vocabularies, with pool-ID theming, explicit depth budgets, and seed-from-placement as a viable alternative to stored seeds.
