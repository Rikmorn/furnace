# F4.5 editor-chrome precedent research — 4-lane sweep (2026-07-29)

Feeds the F4.5 UX-stage charter brainstorm. Companion to
`2026-07-15-f2-tool-ux-precedent-research.md` (tool *semantics* — brushes, masks,
stamps — deliberately not re-covered here). Subject: CHROME — layout/panel/overlay
architecture, tool-options placement, mode communication, error surfacing, undo
scoping, keyboard vocabularies.

Method: four isolated web-grounded research lanes run in parallel (official manuals,
docs, release notes, and first-party trackers preferred; citations inline). Lanes:
(1) mainstream 3D DCC + game-editor chrome, (2) voxel/sculpt-native editors,
(3) mode communication / multi-step gestures / errors / undo scoping / selection
feedback, (4) the canvas-maximal 2D lineage + hotkey vocabularies. Each lane report
is preserved in full below the synthesis.

Constraints the lanes were briefed against: the canvas-stability hard rule (nothing
about selection or tool switching may resize the 3D canvas — user decision record,
2026-07-27), the Photoshop-model direction seed, single-WebGPU-canvas hosts,
DESIGN.md's Attention Rule (color = attention, ≤10% accent), desktop-app posture,
RMB-held-WASD fly camera, Safari-primary.

## Synthesis — what converges across lanes

1. **The overlay direction is shipped precedent, with conditions.** Unity Scene View
   Overlays (2021.2+) is the one shipped system doing floating-but-dockable palettes
   compositing OVER a size-stable 3D canvas — edge-snap docking, collapse-to-icon
   when docked, a per-overlay visibility menu (Spacebar), toggle-all on one key
   (backtick), layouts saved as presets. Figma UI3's 2024 backlash documents exactly
   what breaks when palettes float WITHOUT those conditions (no edge anchoring, no
   full-hide, canvas leaking around panel gaps): docked came back as the default.
   Adopt floating-but-dockable, never floating-only.
2. **The always-armed tool-options strip wants to be opaque and fixed-position.**
   UE 5.6 retired its translucent floating viewport-toolbar "bubbles" after 12 years
   for legibility against arbitrary 3D content; Photoshop's Options Bar is the same
   answer (fixed home, content re-renders per tool, geometry never changes).
   Translucent/floating is for secondary, optional surfaces only.
3. **Hide-all-chrome is a category constant** — Photoshop `Tab`, Figma `⌘\`, Unity
   backtick, UE `F11`, Godot distraction-free, Blender `Ctrl+Space` maximize. Six
   independent implementations converge. Load-bearing detail: restore must return
   the EXACT prior state, not a recomputed default.
4. **Canvas stability separates the two chrome families.** Blender regions and
   Godot/Houdini splits resize sibling content on toggle — tolerated only because
   toggles are rare, deliberate, session-long. Unity overlays composite instead.
   Under our hard rule the compositing family is the only admissible one; the
   load-bearing mechanism is that overlays are absolutely-positioned layers above a
   size-locked canvas, NOT flex/grid siblings that reflow it. An "overlay" built as
   DOM that reflows the canvas div silently reintroduces the banned class.
5. **Tool arming is multi-channel and cheap.** Blender combines toolbar highlight +
   cursor glyph + a Tool Header (live params) + a status bar whose keymap hints
   re-render PER ARMED TOOL ("which click does what", verbatim our pain). Axiom
   piggybacks arming on the one UI element the player already fixates on. The
   in-canvas ghost/target preview (Axiom target block, Dreams' tool-as-in-world-
   object) is the channel that costs zero chrome and cannot violate canvas
   stability.
6. **Tool-scoped options, not one shared grey-out form.** Axiom renders a tool's
   options panel only for that tool's fields; MagicaVoxel/Qubicle/VoxEdit are
   unanimous that material/palette selection and tool arming never auto-couple.
   The category answer to our swatches-active-under-Dig pain is conditional
   RENDERING (don't show what the tool ignores), not greying and not auto-arming.
7. **Forms: commit-first, adjust-after.** Blender's "Adjust Last Operation" (F9)
   floating panel — tweak the just-executed operation's params with live re-run —
   is the precedent that replaces giant pre-configuration forms, PROVIDED defaults
   are sane. CAD's mid-gesture numeric entry (SketchUp Measurements box, Fusion
   dimensions: type a number inside the gesture, Enter commits) fits our two-point
   segment. Photoshop scrubby label-sliders and Axiom's drag-slider-with-Ctrl-click-
   exact-entry answer "bounded numerics as raw inputs". ZBrush LightBox (thumbnail-
   first tabbed browser) fits the stamp picker. Dreams: progressive disclosure only
   works if the advanced tier is absent, not collapsed-but-rendered.
8. **Undo: nobody silently merges two histories behind one chord.** Blender (one
   visible stack over heterogeneous backing stores) has a 20-year trail of
   mode-transition undo bugs at exactly that seam; VS Code routes ⌘Z by focus and
   still accrues confusion issues; Photoshop sidesteps via per-document named
   History lists where the panel, not the chord, is primary. The shipped mitigations
   are (a) a VISIBLE named undo target ("Undo: dig at …") and/or (b) focus/mode
   routing — or deleting one history outright where product scope allows.
9. **Errors: two tiers, severity = color + position, cancel must be cooperative.**
   UE splits ephemeral toasts from a durable categorized Message Log; Godot splits
   developer console noise from attention-demanding errors; Blender is retiring our
   exact status-line defect right now (2026 notifications proposal #130427 /
   PR #149609 — reports as status-bar text indistinguishable from success).
   Toast stacking needs a cap policy from day one (UE's documented complaint).
   UE's FScopedSlowTask: cancellation is a polling contract on the job, not a
   button — a cancel affordance without the contract teaches users cancel lies.
10. **Hotkeys: letters gated on RMB state is the shipped answer.** Unity and UE both
    ship bare-letter tool keys (Q/W/E/R…) ALONGSIDE RMB-held-WASD fly; the same
    physical key disambiguates purely on current mouse-button state, re-polled (not
    a latched flag — documented UE regression when the gate drifts). Family keys +
    Shift-cycle within a family (Photoshop) is the vocabulary that scales to ~12
    tools without a memorization cliff; the number row is semantically taken in the
    category (opacity/hotbar). At-cursor radials (Krita pop-up palette, ZBrush
    spacebar) only pay off pre-populated and on an uncontested trigger. Safari-
    reserved chords recorded in lane 4 (⌘W/⌘Q/⌘T/⌘N non-interceptable; bare letters,
    brackets, F-row, Esc safe).
11. **Selection-in-cluster: discrete color tiers on an outline pass.** Blender's
    none/selected/active three-tier outline (black/orange/yellow) is the direct
    precedent for "which flag in the cluster is selected"; the highlight must be
    independent of surface color (an outline/stencil pass, not a tint — our
    markers-on-magenta wash already demonstrated the tint failure). Marching ants
    is a 2D region idiom that does not transfer. Reuse the existing `--primary`
    selection hue for "active", a desaturated variant for "selected", per the
    Attention Rule budget.
12. **Multiple view areas / workspaces.** Blender workspaces = whole-layout-per-task
    tabs, persisted atomically in the document — the precedent IF multiple view
    arrangements are wanted. 3D-Coat Rooms show the same idea failing when the
    workflows are interleaved rather than sequential phases. UE's Content Drawer
    contributes the transient-by-default / explicit-promote-to-docked lifecycle —
    the right shape for surfaces needed briefly (world browser, load/save).
13. **Genuine precedent gaps (our risk, name honestly).** The horizontal slice view
    has no voxel-art-editor precedent (MagicaVoxel's "layers" are visibility groups,
    not a clip plane; Qubicle's slice is a whole-context mode swap) — nearest kin is
    CAD/CT section viewers. And blending live scene/entity editing with volumetric
    sculpting in ONE chrome is less-precedented than it feels: Teardown deliberately
    split them into two tools. Both stay deliberate furnace choices, not pattern
    adoptions.

# Lane 1 — mainstream 3D DCC and game-editor chrome

## Blender 2.8→4.x

**Pattern: Areas/Regions as in-canvas docked strips (T toolbar, N sidebar, Tool Settings header).**
The 3D Viewport editor area is subdivided into *regions*: the main viewport, an optional left Toolbar (`T`), an optional right Sidebar (`N`), a Header, and a Tool Settings strip. Toggling `T`/`N` resizes the visible 3D content — these are not overlays, they are siblings in the same area that share width ([Regions — Blender Manual](https://docs.blender.org/manual/en/3.6/interface/window_system/regions.html)). Tool-specific options live in three redundant places simultaneously: the Tool Settings region below the header, the Tool tab of the Properties editor, and Sidebar ▸ Tool ▸ Active Tool ([Tool System — Blender Manual](https://docs.blender.org/manual/en/latest/interface/tool_system.html)) — a documented complaint among Blender's own users ("Tool settings are on too many places," [devtalk.blender.org](https://devtalk.blender.org/t/tool-settings-are-on-too-many-places/7387)).
*Applicability:* the one Blender mechanic furnace should **not** copy structurally — it resizes the render surface on toggle, exactly the class the canvas-stability rule forbids. It survives in Blender only because `T`/`N` are rare, deliberate, session-long toggles, never automatic per-tool or per-selection changes. Furnace's Dig→Smooth (+44px) resize is the automatic case, which Blender's own model would *also* fail.

**Pattern: "Adjust Last Operation" floating corner panel.**
A small panel appears bottom-left immediately after an operation completes, letting the user tweak that operation's last-used parameters; it can be recalled with `F9` after dismissal, and hidden globally via View ▸ Adjust Last Operation ([Undo & Redo — Blender Manual](https://docs.blender.org/manual/en/latest/interface/undo_redo.html)).
*Applicability:* strong precedent for a **transient, floating, non-reflowing** post-action options panel — answers "where do armed-tool options live" without touching layout. Good fit for stamp-commit / brush-stroke param tweaks.

**Pattern: Workspace tabs, each a fully independent, persisted layout.**
Each Workspace tab owns its own complete area tree; switching tabs swaps the whole layout, and the layout is saved *inside the document* ([Workspaces — Blender Manual](https://docs.blender.org/manual/en/latest/interface/window_system/workspaces.html)).
*Applicability:* the category-proven way to give distinct jobs their own saved arrangements without cramming both into one layout.

**Pattern: `Ctrl+Space` area maximize.**
Expands the area under the cursor to fill the window; the same shortcut restores the prior state exactly ([Areas — Blender Manual](https://docs.blender.org/manual/en/2.82/interface/window_system/areas.html)).
*Applicability:* a cheap, reversible full-bleed escape hatch — same job as a hide-all-chrome chord, scoped to "maximize one area".

**Pattern: Pie menus (built-in).**
`Z` opens a shading pie, `~` a view pie — both in the default keymap ([Default Keymap — Blender Manual](https://docs.blender.org/manual/en/2.90/interface/keymap/blender_default.html)). A separate optional add-on replaces linear menus with pie equivalents — opt-in, not default.
*Applicability:* zero-footprint hold-key radial menus are a real category precedent for exposing a handful of options with no permanent chrome cost.

**Pattern: Viewport Overlays popover (show-flags).**
A single dropdown in the viewport header exposes grid/wireframe/stats/gizmo toggles as checkboxes in one popover ([Viewport Overlays — Blender Manual](https://docs.blender.org/manual/en/latest/editors/3dview/display/overlays.html)).
*Applicability:* the clean home for view-mode/debug toggles — directly relevant to the shading (`flat`/`normals`) control gap.

## Unity Scene View Overlays (2021.2+) — closest shipped precedent

The most load-bearing research target: the only shipped system doing "floating/dockable palettes over a single, size-stable 3D canvas."

**Mechanics.** Overlays are persistent, customizable, floating-or-docked panels layered *on top of* the Scene view render surface — the canvas is a single continuous target; overlays composite over it rather than sharing layout space with it ([Unity Manual: Overlays](https://docs.unity3d.com/2021.2/Documentation/Manual/overlays.html)). Docking: drag an overlay's handle or header across the Scene view boundary until it highlights, release to anchor to that edge; corners snap-anchor. Multiple docked overlays at one edge rearrange automatically. Non-toolbar overlays auto-collapse when docked; right-click the handle to force Collapse/Expand or reorient Horizontal/Vertical. Floating overlays can overlap; click brings to front. `Spacebar` opens the overlay menu (toggle visibility per overlay); `` ` `` toggles *all* overlays — the hide-all-chrome affordance. Layouts save as presets (`.wpr`), reloadable per-project, and persist inside saved Editor window layouts.

**Tool options placement.** A dedicated **Tool Settings overlay** shows only the active tool's parameters — contextual, so irrelevant controls are never shown ([Unity Overlays manual](https://docs.unity3d.com/6000.0/Documentation/Manual/overlays.html); rationale at [foundations.unity.com/patterns/overlays](https://www.foundations.unity.com/patterns/overlays)).

**Why it works / failure modes.** The design rationale explicitly frames overlays as solving docked-panel screen-space cost while keeping background visibility — the "wasted real estate" pain. The guarded-against risk is clutter: default-collapsed states and contextual visibility keep the surface from becoming a wall of always-on widgets. Structurally implied risk: floating overlays can occlude 3D content — Unity's answer is collapse-to-icon plus repositionable docking, not avoidance.

*Applicability:* the strongest direct precedent for the Photoshop-model direction, proving it compatible with a single stable-size 3D canvas — overlays never reflow the render target.

## Unreal Engine 5

**Pattern: the Modes system.** A toolbar dropdown switches the editor's primary behavior (Select, Landscape, Foliage, Mesh Paint…); each mode opens its own Modes panel, docked left ([Level Editor Modes — UE5 Docs](https://dev.epicgames.com/documentation/unreal-engine/level-editor-modes-in-unreal-engine)). The panel is a normal dock tab.
*Applicability:* "docked panel whose CONTENT is contextual" and "true overlay" are two distinct, both-legitimate answers to "where do tool options live" — the difference is whether the panel's *existence* is negotiable real estate.

**Pattern: viewport toolbar — a directly relevant regression.** UE 5.6 redesigned the viewport toolbar (first change since 2013): "gone are the floating transparent bubbles, now we have a more standard opaque bar," with category-grouped fixed locations and overflow handling ([Unreal Sensei on UE 5.6](https://www.unrealsenseinewsletter.com/news/how-unreal-engine-5-6-refreshes-the-unreal-editors-interface); [Viewport Toolbar — UE5.8 Docs](https://dev.epicgames.com/documentation/unreal-engine/viewport-toolbar)).
*Applicability, important nuance:* Epic moved **away from** translucent floating bubbles because of discoverability/legibility problems against varied 3D content. A genuine counterweight to a pure "overlays everywhere" reading: the PRIMARY tool-options strip may want to be an opaque, fixed-geometry bar; secondary palettes stay legitimately floating.

**Pattern: drawers — Content Drawer summon/dismiss.** `Ctrl+Space` summons the Content Drawer as a floating panel over the viewport; it auto-minimizes on focus loss, and a "Dock in Layout" button converts it to a permanent panel ([Content Drawer — UE5.8 Docs](https://dev.epicgames.com/documentation/unreal-engine/2-16-content-drawer)).
*Applicability:* a different overlay lifecycle — *transient-by-default, promotable-to-permanent by explicit action*. Right shape for surfaces needed briefly (world file browser, load/save picker).

**Pattern: layout persistence.** Tab/floating-window layout auto-persists; `Window ▸ Save Layout As` / Export / Import give named layouts ([community documentation](https://www.cbgamedev.com/blog/quick-dev-tip-49-ue4-ue5-save-load-layouts)).
*Applicability:* UE treats ALL window/panel/floating state as one persisted blob. Persisting panel positions but not widget state (filters, selected tab) reproduces furnace's "flag filters reset on mount" tax.

**Pattern: Immersive Mode / hide UI.** `F11` toggles Immersive Mode (viewport fills the window, restorable by the same key); `G` toggles UI during Play ([UE forums](https://forums.unrealengine.com/t/allow-fullscreen-mode-in-immersive-mode/99)).

**Pattern: status/error surfacing — two-tier.** Transient toasts fade in bottom-right for short-lived events; a persistent, categorized **Message Log** window holds detailed, reviewable error/warning history ([Message Log — Unreal Community Wiki](https://unrealcommunity.wiki/message-log-4wzqj97j)).
*Applicability:* directly answers "failures typographically identical to successes, silently cleared" — ephemeral toast for the moment + durable categorized log for the history.

## Godot 4 and Houdini (brief)

**Godot 4** uses a conventional split-dock model — bottom panel + side docks are literal splits of one window tree ([Customizing the interface — Godot 4 Docs](https://docs.godotengine.org/en/stable/tutorials/editor/customizing_editor.html)); opening/closing them **does** resize the 3D viewport — architecturally the same family as dockview, confirming resize-on-toggle is a tolerated tradeoff in that family, not a solved problem. Godot ships **Distraction Free Mode** (`Ctrl+Shift+F11`) hiding all docks ([GitHub issue thread](https://github.com/godotengine/godot/issues/18655)).

**Houdini** offers fully general pane tiling ([Desktops and panes — SideFX Docs](https://www.sidefx.com/docs/houdini/basics/panes.html)) plus **radial menus** on a hold-key at the cursor, dismissed on release, zero permanent layout cost, scriptable per pane-context ([Radial menus — SideFX Docs](https://www.sidefx.com/docs/houdini/basics/radialmenus.html)).
*Applicability:* the cheapest-footprint precedent surveyed — an alternative/complement to a persistent Tool Settings overlay for rarely-used options.

## Lane 1 anti-patterns

1. **Region-resize-on-automatic-change.** Blender's Toolbar/Sidebar and Godot/Houdini splits resize sibling content on toggle — tolerable only because the toggle is rare and manual; furnace's equivalent fires automatically per tool switch.
2. **Translucent floating bars over 3D content.** UE's pre-5.6 toolbar had legibility problems severe enough that Epic replaced it after over a decade.
3. **Silent auto-dismiss with no armed-state signal.** UE's Content Drawer auto-minimizes with no persistent indicator of pinned-vs-gone — the same failure shape as invisible tool arming.
4. **Redundant tool-settings homes.** Blender exposes the same tool parameters in three UI locations — flagged by its own community as a defect.
5. **Single mutable status channel** — the anti-pattern UE's toast+log split exists to fix.

## Lane 1 load-bearing mechanisms

- **Unity overlays require compositing over a fixed render target**, not a flex/grid layout sharing space with the canvas. "Overlays" as DOM that reflows a canvas div silently reintroduces the resize bug while *looking* like the Photoshop model.
- **Unity's collapse-to-icon + per-overlay visibility menu is what prevents occlusion becoming clutter.** Floating overlays without a collapse state and a "what's currently shown" menu reproduce invisible-arming in a new location.
- **UE's opaque, fixed-position primary toolbar is what makes it legible against arbitrary 3D content.**
- **UE's hide-all and Blender's `Ctrl+Space` both restore the exact prior state, not a recomputed default.**
- **UE's layout persistence covers floating-window state, docked-tab state, and per-widget state as one blob** — persisting geometry only is the "flags reset on mount" shape.
- **Blender workspace tabs swap the whole layout atomically**, not incrementally — N independent stored layouts, not one mutable global mutated per tab.
- **UE's Content Drawer duality depends on promotion being a first-class visible button**, not an implicit side effect.

# Lane 2 — voxel & sculpt-native editors

## 1. The game's own persistent selector *is* the armed-tool indicator — Axiom

Axiom (Minecraft world-editing mod; closest domain match: first-person fly-camera + voxel edits) doesn't invent a "current tool" widget. It repurposes Minecraft's hotbar: a dedicated slot holds the Builder Tool, and `Left Alt` + scroll cycles tools — the vanilla item-select UI *is* the arming feedback, because the engine already renders the selected slot with a highlight the player reads unconsciously. Deep tools live in a separate, explicitly-toggled "Editor Mode" (`Right Shift`) with a docked desktop-style UI; the lightweight "Builder Mode" stays a thin HUD so the 3D view is never obstructed by default ([Editor Mode](https://axiomdocs.moulberry.com/editor/intro.html), [Introduction](https://axiomdocs.moulberry.com/)).

**Why it works:** the indicator costs zero new pixels — it rides on UI already in the user's foveal path. **Applicability:** furnace has no hotbar to piggyback on, but the *principle* ports: put the active-tool indicator in the foveal path (near cursor or canvas edge), not a side rail requiring a saccade. Direct hit on a filed pain: the critique measured furnace's active tool as the *faintest* text in its row (5.48:1 vs 10.75:1 inactive) — the opposite of Axiom, where selected state structurally reads as selected.

## 2. Tool-scoped floating options, not one shared giant form — Axiom

Selecting a tool opens a "Tool Options" window scoped only to that tool's fields; nothing renders for fields the tool doesn't use ([Tools](https://axiomdocs.moulberry.com/tools/intro.html)). No persistent do-everything inspector greying out irrelevant rows — the panel's *existence* is conditional on relevance.

**Why it works:** eliminates the grey-out problem by not building the shared surface. **Applicability:** answers "material swatches active under tools that ignore material" — don't grey the swatch rail conditionally; don't render it when the active tool is material-blind. **Load-bearing:** each tool owns its options schema; a central panel unioning all tools' fields (the source of furnace's 11+-field flat forms) cannot get this property without decomposition first.

## 3. In-world ghost/target preview before commit — Axiom, MagicaVoxel, Dreams

Axiom highlights the exact "Target Block" the stroke is about to touch, live, before the click ([Tools](https://axiomdocs.moulberry.com/tools/intro.html)). MagicaVoxel's brush modes + shape pickers render the pending shape at the cursor as you hover ([Interface](https://leonida.gitbooks.io/magicavoxel-user-reference-manual/content/interface/)). Dreams represents tools as in-world "gadgets" the cursor holds — the tool's identity and its effect area are the same object in the scene ([How Media Molecule designed a toolset for Dreams](https://www.gamedeveloper.com/design/how-media-molecule-designed-a-fun-and-robust-toolset-for-i-dreams-i-)).

**Why it works:** the feedback surface *is* the canvas — no secondary surface to sync, no canvas-resize risk. **Applicability:** the strongest match to the canvas-stability rule; extend the existing stamp ghost vocabulary (Enter/Esc) uniformly to sculpt brushes and selection tools. **Failure mode:** on a near-monochrome palette an in-world ghost needs a *non-hue* differentiator (outline weight, dash, opacity) — color is reserved for attention.

## 4. Vertical tool/mode/shape rail, decoupled from the color palette — MagicaVoxel

MagicaVoxel's modeling rail (right): brushes, Attach/Erase/Paint mode buttons, shape toolbox, mirror/axis toggles, then separately Selection tools, Clipboard, transform. The color palette (255 swatches + HSV/RGB) is a wholly separate left panel ([Interface](https://leonida.gitbooks.io/magicavoxel-user-reference-manual/content/interface/)). Mirror axes are independent toggles ([Mirror interface](https://magicavoxel.fandom.com/wiki/Mirror_(brush)_(interface)); in-viewport mirror-plane visual unconfirmed).

**Why it works:** color selection and tool/mode selection are orthogonal state that never auto-couples — picking a swatch never arms Paint mode. **The category's answer across MagicaVoxel, Qubicle ([edit-mode palette buttons](https://getqubicle.com/learn/article.php?id=3)), and VoxEdit ([mode buttons](https://medium.com/@rodrigogsherrero/voxedit-the-sandbox-voxel-editor-12018c60d9de)) is: don't auto-switch.** Furnace's swatch pain is a *visibility* problem, not a *coupling* problem — solve by conditional rendering (pattern 2), not auto-arming.

## 5. Layer visibility groups vs. spatial slice — a real gap, not a hidden precedent

Verified via the MagicaVoxel Wiki: its Layer panel is **object-visibility grouping** (8 fixed-color layers hiding/showing *groups of objects*), not a Y-plane clip ([Layers interface](https://magicavoxel.fandom.com/wiki/Layers_(interface))). No true axial slice/CT-style cross-section found in MagicaVoxel, Qubicle, or VoxEdit docs. Qubicle's closest analog is a **mode toggle** (`Space`) between "matrix edit" and "slice edit" — a whole-context swap, not a clip ([Quick Guide](https://getqubicle.com/learn/article.php?id=3)).

**Applicability:** furnace's horizontal slice is field-native (dense volume, not sparse objects); nearest kin is CAD/CT slice viewers. A genuine gap in prior art — flagged rather than force-fitted.

## 6. Workspace-per-task chrome, same panel differently populated — 3D-Coat "Rooms"

3D-Coat's Rooms (Sculpt/Retopo/UV/Paint/Render) are tabs swapping the entire tool/panel configuration per pipeline stage ([Workspaces Rooms](https://3dcoat.com/documentation/manual/workspaces-rooms/)). The Layers Panel is the *same chrome slot* across rooms carrying different semantic content ([The Layers Panel](https://3dcoat.com/documentation/manual/workspaces-rooms/paint/the-layers-panel/)).

**Why it works:** one panel location, one interaction grammar, reused for structurally different data. **Failure mode:** Rooms work because each is a phase of one linear pipeline; forcing *concurrent, interleaved* workflows into discrete rooms fights how the tool is used. The transferable piece: reuse one panel slot's chrome across workflows with different bound data, rather than parallel surfaces duplicating layout logic.

## 7. At-cursor popup menus — ZBrush spacebar vs Axiom's context menu

ZBrush's customizable popup (`Spacebar`) opens a user-built menu at the cursor. Payoff is real once populated — but it ships **empty by default**, needs manual curation, and the binding permanently collides with remap attempts; documented frustration calls the default "useless" ([zbrushcentral](https://www.zbrushcentral.com/t/disable-spacebar-popup-menu-hotkey/207120)). Axiom's Alt+context menu is the disciplined counter-example: populated out of the box, fixed sections, tinted-vs-greyed capability states ([Context Menu](https://axiomdocs.moulberry.com/contextmenu/intro.html)).

**Load-bearing distinction:** at-cursor popups pay off only if (a) pre-populated with sane defaults and (b) the trigger key is uncontested.

## 8. Thumbnail-first, tabbed asset browser — ZBrush LightBox

`,` toggles LightBox: a tabbed browser (Projects/Tools/Brushes/Materials/Alphas/…) where every entry is a thumbnail, double-click to load ([Lightbox — Maxon docs](https://help.maxon.net/zbr/en-us/Content/html/getting-started/basic-concepts/lightbox/lightbox.html)).

**Applicability:** maps to the stamp picker (hall/maze/cave/scatter) and material swatches — a thumbnail-first picker gives a fast default-preset entry point before raw fields.

## 9. Progressive disclosure over exhaustive sliders — Dreams "stealth create"

Media Molecule deliberately avoided "endless menus, and endless sliders, and endless settings" — tools default to their simplest usable form and reveal deeper controls only as the user opts in; gesture-based reach/zoom replaces numeric fields for common continuous adjustments ([Game Developer interview](https://www.gamedeveloper.com/design/how-media-molecule-designed-a-fun-and-robust-toolset-for-i-dreams-i-)).

**Applicability:** the precedent-backed answer to huge flat forms + bounded-numbers-as-raw-inputs. Axiom's slider mechanics are the concrete pattern: draggable slider for the common range, `Ctrl+Click` to type an exact out-of-range value ([Editor Mode](https://axiomdocs.moulberry.com/editor/intro.html)). **Failure mode:** disclosure only reduces load if the advanced tier is genuinely hidden, not collapsed-but-rendered.

## Briefly noted

- **Goxel**: minimal always-visible icon rail where each icon opens a *detachable* panel — panels are on-demand, floatable ([GitHub source](https://github.com/guillaumechereau/goxel/blob/master/src/gui/palette_panel.c)). Supports the overlay direction: icon rail stays cheap, panels are transient.
- **VoxEdit**: palette panel collapses to give layers more room — an explicit real-estate tradeoff exposed to the user.
- **Teardown**: caution, not a pattern. Its shipped Level Editor is a scene-graph/property editor; voxel sculpting happens in an **external** tool (VoxTool) ([Level Editor wiki](https://teardown.fandom.com/wiki/Level_Editor), [VoxTool](https://teardowngame.com/voxtool/)). A shipped voxel game deliberately did *not* blend entity editing and voxel sculpting into one chrome — a considered rejection worth naming, since furnace committed to the opposite.

## Lane 2 anti-patterns

1. User-authored-from-blank UI as the primary quick-access surface (ZBrush spacebar).
2. Coupling color/material selection to tool arming — no surveyed tool does it.
3. Full workspace swap for interleaved (not sequential) workflows.
4. Greying out irrelevant controls instead of not rendering them.
5. Blending scene editing and volumetric sculpting without precedent-checking the mechanism (Teardown's split is a signal, not a mandate).

## Lane 2 load-bearing mechanisms

- **Ghost/target preview** satisfies canvas-stability only if it renders *in the 3D pass*, not as a content-sized DOM overlay.
- **Tool-scoped options panels** kill the grey-out problem only if each tool's schema is authored independently.
- **At-cursor popups** work only pre-populated and on an uncontested key.
- **Reused panel-slot-with-different-data** reduces learning cost only if the interaction grammar is identical across modes reusing it.
- **Progressive disclosure** works only if the hidden tier is absent from the DOM/state on first render.

# Lane 3 — mode communication, multi-step gestures, error surfacing, undo scoping, selection feedback

## 1. Armed-tool / mode communication

**Blender's three-channel combo — cursor, tool header, status-bar keymap.** Blender never relies on a single signal: toolbar highlight + viewport cursor change (*which tool*), the Tool Header showing live settings (*its parameters*), and the Status Bar's left segment showing "mouse button shortcuts and the keymap of the active tool" — dynamically, per tool — plus an **Alt Click Tool Prompt** overlay of switch hotkeys ([Status Bar — Blender Manual](https://docs.blender.org/manual/en/latest/interface/window_system/status_bar.html)). Three channels, three jobs; none redundant.

**Applicability:** the status-bar keymap hint updating per-armed-tool directly answers "which click does what" with one text-driven status region — no canvas real estate, no stability risk. A cursor-glyph change per armed tool is the second cheap channel.

**Unreal's PIE colored viewport border — UNVERIFIED this session** (official docs only confirmed toolbar changes and Eject/F10; [Playing and Simulating — UE 5.8 docs](https://dev.epicgames.com/documentation/en-us/unreal-engine/playing-and-simulating-in-unreal-engine)). Do not cite as fact without checking a live UE build.

## 2. Multi-step gesture guidance

**Blender's modal-tool prompt line.** Knife's status bar reads, verbatim: *"LMB: define cut lines, Return/Spacebar: confirm, Esc or RMB: cancel, E: new cut, Ctrl: midpoint snap (OFF)…"* — action, live toggle state, and the confirm/cancel vocabulary in one line ([Knife Tool — Blender Manual](https://docs.blender.org/manual/en/2.81/modeling/meshes/editing/subdividing/knife.html)). Loop Cut is stepped (click/Enter confirms placement, second confirms slide, Esc cancels all). **The confirm/cancel vocabulary is fixed across all modal tools** — Enter/Spacebar confirms, Esc/RMB cancels — one universal grammar.

**Blender's "Adjust Last Operation" (F9) as the alternative to pre-configuration forms.** After any operator, a small floating panel (bottom-left, or F9) tweaks the just-executed operator's parameters, re-running live ([Undo & Redo — Blender Manual](https://docs.blender.org/manual/en/2.83/interface/undo_redo.html)). **This answers the huge-form pain directly: commit first with sane defaults, adjust after** — and it is where dials/sliders belong, not a 60-row pre-form.

**CAD inline dimension entry (Fusion 360 / SketchUp).** A two-click gesture accepts a typed number mid-gesture overriding the mouse value, committed on Enter — SketchUp's Measurements box ([SketchUp Community](https://forums.sketchup.com/t/entering-all-dimensions-in-measurements-nee-vcb/37792)); Fusion sketch dimensions ([Autodesk Help](https://help.autodesk.com/view/fusion360/ENU/?contextId=SKT-CREATE-DIMENSIONS)). Load-bearing: the numeric override lives **inside the gesture** — direct precedent for the two-point segment (type a length while dragging, Enter).

**Applicability:** adopt the fixed vocabulary (Enter/Esc, everywhere) plus a single-line, tool-adjacent prompt ("click second point · Enter to commit · Esc to cancel") — canvas-safe; eliminates "armed-but-unanchored gesture shows nothing" at the source.

## 3. Error/refusal/notification surfacing

**Blender is mid-fight with exactly this bug.** Current shipped behavior renders reports in the status bar with no strong distinction from info; Blender's tracker holds an open 2026 proposal, [#130427 "Notifications"](https://projects.blender.org/blender/blender/issues/130427), plus active PR [#149609 "UI: Pop-up Report Notifications"](https://projects.blender.org/blender/blender/pulls/149609) — toast banners sliding up from the window bottom, stacking rather than overwriting (read via search index; direct fetch 403'd — treat wording as reported). **Category-leading evidence the status-line pattern is a recognized defect.**

**Godot: severity as color + position, filterable.** Errors red, warnings yellow, logs plain; auto-open on Play; severity toggles + text filter ([Output panel — Godot docs](https://trinovantes.github.io/godot-docs/tutorials/scripting/debug/output_panel.html)). `push_warning()` routes to the Debugger's Errors tab, not Output — a deliberate split of console noise from attention-demanding items.

**Unreal: Message Log (persistent, categorized) vs toast (ephemeral).** Documented complaint: compile-error toasts linger, stack, and obscure content ([UE forums](https://forums.unrealengine.com/t/dismiss-6x-errors-warnings-reported-is-there-really-no-way-to-disable-stacking-popup-error-messages/1916757)) — **unmanaged toast stacking becomes its own obstruction**; cap/grouping policy is day-one work.

**Background jobs — `FScopedSlowTask` as the progress+cancel contract.** Named steps, optional progress dialog, and `ShouldCancel()` polled by the job's own loop — cancellation is **cooperative** ([FScopedSlowTask — UE 5.6 docs](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Core/Misc/FScopedSlowTask)). A cancel button with no polling contract on the analyzer/x-ray/bake side is a lie.

## 4. Undo scoping — the load-bearing lane

**Blender: one user-visible stack, multiple backing mechanisms — and the seams are where it breaks.** Developer docs describe a single relative undo stack gathering steps of different origin (global/memfile snapshots vs mode-local incremental steps for sculpt/paint) ([Undo System — Blender Developer Docs](https://developer.blender.org/docs/features/core/undo/); read via search index, direct fetch 403'd). Documented mode-transition bug trail at that seam: sculpt lost on undo after leaving sculpt mode ([#37796](https://developer.blender.org/T37796)); undo stuck when sculpt mode entered via undo ([#84470](https://developer.blender.org/T84470)); regression crossing back into a memfile step ([#82388](https://developer.blender.org/T82388)). **The same seam recurring — precedent that one-affordance-over-heterogeneous-stores is a known hard problem, not a quick fix.**

**Blender's mitigation is a visible list, not a smarter merge.** Undo History (Edit ▸ Undo History) shows every step as a named, clickable entry — reducing the *cost* of ambiguity rather than removing it.

**Photoshop's History panel: undo as a spatial list, not a chord.** Every state a named row; click to jump; linear vs non-linear modes; **per-document** — no cross-document ambiguity because there is no cross-document chord ([Manage image states — Adobe Help](https://helpx.adobe.com/photoshop/desktop/get-started/set-up-toolbars-panels/manage-image-states.html)).

**VS Code: routed by focus, seam still visible.** Separate undo domains routed by focus ([#113653](https://github.com/microsoft/vscode/issues/113653)); undo can itself switch focus across files, generating warning requests ([#106192](https://github.com/microsoft/vscode/issues/106192)) and cross-file revert bugs ([#638](https://github.com/microsoft/vscode/issues/638)).

**No shipped editor found silently and correctly merges two logically distinct histories behind one chord with no user-visible seam.** The honest paths: (1) route by explicit focus/mode AND pair with a visible affordance naming the target ("Undo: dig at (12,4,8)" vs "Undo: rename entity"); or (2) make the undo affordance context-aware (label names its target) — or delete one history where product scope allows.

## 5. Selection feedback in 3D — disambiguating a cluster

**Blender's three-tier outline color.** Black outline unselected, **orange** selected-not-active, **yellow** the single active object — a multi-select cluster always has exactly one visually distinguished "the one" ([Selecting Objects — Blender Manual](https://docs.blender.org/manual/en/latest/scene_layout/object/selecting.html)). Hue + saturation tiers, not shape — directly transferable to flag markers.

**Unity/Unreal: outline via post-process/stencil**, parameterized by color/width, decoupled from the object's own material ([Roystan outline shader](https://roystan.net/articles/outline-shader/); [UE custom-depth thread](https://forums.unrealengine.com/t/how-to-show-selection-outline-highlight-in-perspective-viewport/282541)). Matters because furnace's markers already vanish on magenta — an outline pass independent of surface color is the category fix; a tint would wash the same way.

**Marching ants does not transfer** — a 2D region-boundary idiom ([Wikipedia](https://en.wikipedia.org/wiki/Marching_ants)); no shipped 3D equivalent found. Use discrete color tiers instead.

## Lane 3 anti-patterns

- Toast stacking with no cap/grouping (UE's documented complaint).
- Severity conveyed by tone/position alone, indistinguishable from success (the defect Blender is retiring via #130427/#149609).
- A generic "Undo" affordance over an ambiguous target — known-hard, never casually replicable.
- A cancel button not wired to a cooperative check — teaches users cancel doesn't work.
- Marching ants imported into 3D by analogy.

## Lane 3 load-bearing mechanisms

1. **The status-bar keymap hint is load-bearing only because it's dynamic per armed tool** — a static legend answers nothing.
2. **Adjust-Last-Operation replaces a pre-form only if defaults are genuinely sane** — otherwise the huge form just moves one step later.
3. **The severity split works only if routing is consistent** — one destructive failure still routed through the quiet channel re-breaks it.
4. **Cooperative cancel works only if every long-running loop actually polls.**
5. **Cluster disambiguation must reuse the existing selection hue budget** (`--primary` for active, desaturated for selected) — a new hue breaks the Attention Rule.
6. **Focus-routing reduces confusion only when paired with the visible-list/named-target affordance** — routing alone reproduces VS Code's open issues.

# Lane 4 — canvas-maximal 2D lineage + keyboard vocabularies

## 1. Photoshop's palette system

**Floating/docked duality + icon-collapse rail.** Panels drag to dock, drag away to float, or collapse into a narrow icon rail ([Adobe: dock/undock panels](https://helpx.adobe.com/photoshop/desktop/get-started/learn-the-basics/dock-undock-panels.html), [icon collapse](https://helpx.adobe.com/photoshop/desktop/get-started/learn-the-basics/collapse-expand-icons.html)). The rail is the load-bearing middle state — reachable without full footprint, which floating-only systems lack.

**Workspace presets + save/reset.** `Window > Workspace > New Workspace` snapshots the arrangement; `Reset` restores deterministically ([Adobe: restore workspaces](https://helpx.adobe.com/photoshop/desktop/get-started/learn-the-basics/restore-workspaces.html)). **This is what makes "float anything anywhere" safe long-term** — without a named resettable home, floating drift is one-way entropy. Precisely the gap Figma shipped without.

**Tab / Shift+Tab / F.** `Tab` hides toolbar + options bar + all panels; `Shift+Tab` panels only; `F` cycles screen modes; edge-hover re-summons transiently in full-screen ([photoshopessentials.com](https://www.photoshopessentials.com/basics/photoshop-hide-photoshop-with-screen-modes-and-interface-tricks/)).

**Options Bar as armed-tool parameter home.** Fixed physical location, content re-renders per tool, never resizes the canvas.

**Spring-loaded (quasimode) tools.** Hold a tool's key = temporary tool, release = revert; configurable delay ([Adobe: spring-loaded shortcuts](https://helpx.adobe.com/photoshop/desktop/get-started/set-up-toolbars-panels/spring-loaded-shortcuts.html)). Raskin's *quasimode*: holding makes the mode self-evident ([Wikipedia: quasimode](https://en.wikipedia.org/wiki/Quasimode_(computer_interface))). Community threads document hold-release timing fragility across versions — a real implementation hazard.

**Tool grouping.** `Shift+<letter>` cycles same-lettered families; flyouts reveal hidden siblings ([jkost.com](https://jkost.com/blog/2021/05/30-ways-to-customize-the-photoshop-interface.html)).

**Scrubby sliders.** Hovering a slider's *label* turns the cursor into a drag-hand; `Alt`-fine, `Shift`-coarse — the label is the control; answers bounded-numerics-as-raw-inputs with zero extra widgets.

## 2. Figma UI3 (2024)

Floating panels were the signature move ([Figma blog](https://www.figma.com/blog/figma-2024-we-shipped-it-you-shaped-it/)); backlash was immediate and sustained ([forum: "Forcing UI3 on us is a HUGE mistake"](https://forum.figma.com/share-your-feedback-26/forcing-ui3-on-us-is-a-huge-mistake-let-us-choose-april-30-39150)). Mechanism-level complaints ([forum: fixed panels are back](https://forum.figma.com/suggest-a-feature-11/launched-fixed-panels-are-back-23789)): canvas content leaking in gaps around floating panels (visually distracting, worse for some neurodivergent users); loss of screen-edge muscle memory; no per-panel hide; narrower panels forcing horizontal scroll. Resolution: docked panels returned as default; floating reserved for specific contexts; the surviving win is **Minimize UI** — `⌘\` hides chrome, `⇧⌘\` collapses side panels ([Figma Help](https://help.figma.com/hc/en-us/articles/41414918021271-Hide-or-minimize-the-UI)).

**The lesson:** floating without edge-anchoring and a full-hide hatch is the failure mode, not floating per se.

## 3. In-context controls (no panel round-trip)

**Krita's pop-up palette.** Right-click on canvas spawns a radial at the cursor: tag-filtered brush presets, mini color wheel, swatches, recent colors, rotation dial ([Krita Manual: Pop-up Palette](https://docs.krita.org/en/reference_manual/popup-palette.html)). Zero navigation cost.

**Procreate's edge sliders + QuickMenu.** Persistent edge sliders (size, opacity) with hold-then-drag fine mode ([Procreate Handbook](https://help.procreate.com/procreate/handbook/interface-gestures/interface)); QuickMenu is a customizable 6-slot radial on an assignable gesture ([QuickMenu](https://help.procreate.com/procreate/handbook/interface-gestures/quickmenu)).

**Applicability:** bounded params (radius) don't need a docked form field if a cursor-anchored scrub or radial exists; keep Options-Bar-style docked display for anything read continuously.

## 4. Cross-cutting hotkey vocabularies

- **Number row is spoken for** — Photoshop maps `1–0` to opacity/flow; games reserve it for hotbars. Don't spend it on tool selection.
- **QWER transform rows** (Maya `Q/W/E/R` [Autodesk shortcuts](https://www.autodesk.com/shortcuts/maya); Unity `Q/W/E/R/T/Y` [Unity Manual](https://docs.unity3d.com/Manual/PositioningGameObjects.html)) — a small positionally-adjacent row learned as a chord shape.
- **Single-letter mnemonic tools** scale to Photoshop's ~20 only *because* Shift-cycling + flyouts absorb overflow — the letter picks a *family*. Twelve unrelated letters = the memorization cliff; 4–5 mnemonic families (brush family, select family, stamp family) is the shipped shape.
- **Bracket-resize** — already in furnace; uncontested.
- **X-swap** — one dedicated key for one binary toggle (fg/bg; maps to dig/fill polarity if wanted).
- **Hold-quasimodes** — the same primitive as the existing RMB-fly camera.
- **Double-tap modifiers** — NOT recommended: OS Sticky Keys intercepts repeated modifier taps on both platforms.
- **Leader/pie keys** — high ceiling, but the wrong first rung for a user base (of one) with zero existing tool-hotkey muscle memory.

## 5. Key-conflict analysis: RMB-WASD vs single-letter tools

Both Unreal and Unity gate letters entirely on mouse-button state: UE documents camera movement as "Hold RMB + W" while `Q/W/E/R` tools carry no RMB qualifier ([Viewport Controls — UE docs](https://dev.epicgames.com/documentation/en-us/unreal-engine/viewport-controls-in-unreal-engine)); a UE5.8 forum bug shows the gating logic itself can regress ([forum](https://forums.unrealengine.com/t/in-the-viewport-holding-down-the-right-mouse-button-prevents-the-use-of-the-w-a-s-and-d-keys-for-movement/2734153)). Unity ships the identical shape ([SceneViewNavigation](https://docs.unity3d.com/Manual/SceneViewNavigation.html)).

**Implication:** single-letter tool bindings are safe under RMB-WASD *only if* letter dispatch and fly-camera input are mutually exclusive on RMB state — while RMB is down, letters are consumed by the fly path (captured, not also-listened); tool dispatch re-polls actual button state rather than trusting a latched flag (Sticky Keys / stuck-modifier drift); keydown landing in the same frame as RMB-up must not ambiguously fire a tool switch (Photoshop's tunable spring-load delay is the precedent for that race).

**Browser-reserved chords (Safari-primary):**

| Unsafe (OS/browser owns it) | Safe to bind |
|---|---|
| `⌘W` `⌘Q` `⌘T` `⌘N` — non-interceptable | Bare letters (`Q W E R T Y…`), brackets `[ ]`, `X` |
| `⌘R` (reload), `⌘L` (address bar) | Function row `F1–F12` |
| `Ctrl+Tab` / `Ctrl+Shift+Tab` | `Esc` (universal cancel) |
| `⌘,` (preferences convention — avoid) | `Space` (with careful preventDefault, never in text fields) |
| `⌘D` (bookmark), `` ⌘` `` (window cycling) | `⌘Z/X/C/V` (standard edit ops, semantics must match expectation) |
|  | `Tab` — only with deliberate focus-trap management |

## 6. What the 2D canvas-maximal model does NOT translate to 3D

- **Depth cues under palettes.** A floating panel over raster occludes pixels; over a 3D viewport it can sit *between* camera and gizmo/selection outline, breaking the depth read ([related Godot proposal #2138](https://github.com/godotengine/godot-proposals/issues/2138)).
- **Gizmo/tool occlusion.** Unity Overlays' edge-snap-by-default exists precisely so contextual controls stay adjacent to, never on top of, the content they operate on.
- **Fly-camera pointer capture vs panel drag.** RMB fly wants Pointer Lock/`setPointerCapture` ([MDN: Pointer Lock](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_Lock_API)); a draggable palette wants ordinary capture. One arbiter must decide whether a mousedown starts panel-drag, camera-drag, or gizmo-drag — the same unresolved seam the field pick-path probe already flags.

## Lane 4 anti-patterns

1. Floating panels without edge-snap or a hide-all hatch (Figma UI3's initial ship).
2. Letter keys bound with no regard to mouse-button state, patched reactively.
3. Reusing an already-loaded key lane (number row) — "same job, two answers".
4. Double-tap modifier vocabularies vs OS accessibility interception.

## Lane 4 load-bearing mechanisms

- **Photoshop floating palettes are safe because of Workspace Reset** — no named home, no recovery from drift.
- **Figma's failure isolates the load-bearing piece: edge-anchoring + full-hide**, not floating itself.
- **Spring-loaded tools work because holding is a continuous physical act** — chord/double-tap substitutes break the self-evidence.
- **Krita/Procreate in-context controls work because they spawn at the cursor** — the same radial docked in a panel loses the entire advantage.
- **Unity Overlays' edge-snap prevents gizmo occlusion** — same chrome floating arbitrarily reintroduces it.
