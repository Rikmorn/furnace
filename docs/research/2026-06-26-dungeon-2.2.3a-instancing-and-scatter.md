# GPU instancing + decorative scatter — research for Slice 2.2.3a

> **Status:** Pre-decision research feeding the Slice 2.2.3a ("GPU instancing + decorative
> scatter") spec. Produced by two parallel research rounds (2026-06-26): round 1 surveyed
> prior art; round 2 pressure-tested the two highest-stakes calls. Round 2 **validated** the
> instancing decision (with rationale corrections) and **overturned** the scatter placement
> method. The as-built design will be described in `AGENTS.md` + source on landing.

Grounded in the dungeon's actual pipeline (verified this session): a density `Field`
(air-positive, `>0` air / `<0` rock) → naive Surface-Nets mesh + Rapier `voxels` collider
for caves; box meshes + `cuboid` colliders for rooms; deterministic sfc32 `rng`
(`derive/float/int/bool/pick`); the engine renders **forward**, `MAX_LIGHTS = 16`
(`packages/core/src/frame/lights.ts:150`), per-object model matrix at `@group(2) @binding(0)`
(`packages/core/src/frame/render.ts`), geometry at vertex-buffer slot 0, `pass.draw` with
`instanceCount = 1` today.

**Epistemic key:** `[V]` verified from a cited source · `[K]` established general knowledge ·
`[I]` inference about fit to our pipeline.

## 1. GPU instancing — per-instance vertex buffer (VALIDATED)

**Recommendation:** expose instancing via a **per-instance vertex buffer** (slot 1,
`stepMode: "instance"`), per-instance data = a baked `mat4` (4×`vec4` at attribute
locations 3–6) + an **optional** `vec4` tint (location 7). The instanced pipeline **bypasses
`@group(2)`** and sources `model` from the instance attributes; one instanced shader variant
per supported built-in. `recordDraw` branches to `setVertexBuffer(1, …)` + `drawIndexed(indexCount, count)`.

**Why vertex buffer (not storage, not uniform-by-`instance_index`):**

- Every shipping engine uses the vertex-buffer path for this: learn-wgpu, PlayCanvas
  (`setInstancing`, default full mat4), Babylon thin-instances (a "matrix" instanced
  attribute), and three.js's large-count fallback all encode the mat4 as 4×`vec4` instanced
  attributes [V]. It works identically in WebGPU **core and compatibility** mode with zero
  capability branching [V].
- **Storage-buffer-by-`instance_index`** is rejected as a default: WebGPU's
  `maxStorageBuffersInVertexStage` defaults to **0 in compatibility mode**, and a real slice
  of legacy devices (GL ES 3.1 `MAX_VERTEX_SHADER_STORAGE_BLOCKS = 0`) cannot raise it
  [V: gpuweb compatibility-mode proposal]. (Correction to round 1: this is ~45% of the
  *legacy tier compat exists to serve*, **only if we opt into compat** — `requestAdapter()`
  defaults to **core**, where vertex-stage storage *is* available [V: webgpufundamentals].)
- The real alternative we beat is **uniform-buffer-indexed-by-`instance_index`** — three.js's
  *default* for ≤~1024 instances (compat-safe, simpler shader, zero attribute slots) [V:
  three.js `Instance.js`]. It loses on a hard **count ceiling**: `maxUniformBufferBindingSize`
  64 KB → ~1024 mat4 instances (fewer with tint), forcing a rearchitect for a future
  "thousands of props" scene. Vertex buffers have **no count ceiling** and match ecosystem
  convention. [I]
- **Future-proof:** GPU-driven rendering (compute cull → `drawIndexedIndirect`, instance data
  in a storage buffer) is a *separate, additive* path for thousands–millions of *dynamic,
  culled* instances [V: Toji indirect-draw]. For **hundreds of static decorations set once at
  build**, none of its benefits apply, and adding it later doesn't touch the static path
  (three.js proves the two coexist). Vertex-buffer-now does **not** paint us into a corner. [I]
- **Limits are comfortable:** defaults `maxVertexAttributes: 16`, `maxVertexBuffers: 8`
  [V: MDN]. Geometry (~3–4 attrs, slot 0) + mat4 (4) + tint (1) = ~8–9 of 16 attributes, 2 of
  8 buffers. mat4(64 B)+tint(16 B)=80 B stride, all `vec4`-aligned. [V]

**Layout choices:** bake the `mat4` into the GPU buffer (decode-free vertex shader) but accept
**TRS in the JS API** (mirrors `_recomputeModelIfDirty`). Drop the per-instance normal matrix:
the scatter use case is **uniform scale**, where `mat3(model)` + renormalize yields the
correct normal — document the uniform-scale precondition. [I]

## 2. Decorative scatter — sample the existing mesh, field as a mask (OVERTURNED round 1)

**Recommendation:** place scatter by **area-weighted triangle sampling of the existing
Surface-Nets mesh**, with the **field demoted to a cheap point-eval scalar mask** (density /
keep-out). **Drop Newton-march projection to the `f=0` isosurface** that round 1 proposed.

**Why the flip (three independent reasons):**

1. **It targets a surface nobody sees.** The player sees the **meshed** surface (and collides
   the voxel proxy), not the analytic `f=0` isosurface — Surface Nets quantizes/relaxes
   vertices, so the meshed surface ≠ `f=0`. Decorations Newton-projected to `f=0` float above
   or sink into the *actual rendered* mesh. Disqualifying on its own. [I]
2. **Newton-march doesn't reliably converge on our field.** The field is **non-metric**:
   `smax`/smooth-union breaks the distance/Lipschitz bound (the result is at best a distance
   *lower bound*) [V: Seyb et al. 2019; "Operations on SDF Estimates"], the `1/|∇f|²` step
   blows up at smooth-union welds / noise saddles where `|∇f|→0` [V: arXiv:2003.10397], and
   noise displacement causes overshoot/oscillation [V: Iso-Points, arXiv:2012.06434]. Sphere
   tracing's own convergence assumes a Lipschitz bound we don't have [V: Hart 1996].
3. **It's what production tools all do.** Houdini Scatter SOP, Blender "Distribute Points on
   Faces", and Unreal PCG Surface Sampler **sample the mesh surface** (triangles), then
   filter/weight by attributes — none root-find an implicit field [V: SideFX / Blender / Epic
   docs]. And **we already have the mesh** in the generator (the cave themes mesh the field).

**Method:**

- **Area-weighted triangle pick:** prefix-sum (CDF) over triangle areas → binary-search a
  triangle ∝ area → uniform barycentric sample with the `u = √r1` transform (removes corner
  bias) [V: PBR Book §13.6]. Normal = face normal (or barycentric-blended vertex normals;
  Surface-Nets vertex normals are field-gradient-based anyway). A *single* `∇f` point-eval can
  supply a smooth normal if wanted — that's a cheap eval, not a root-find. [I]
- **One sampleable-surface abstraction:** cave = its triangle list; flat room floor = a
  **rect adapter** (one quad, sampled in 2D). Same `scatter()` consumes both. [I]
- **Field as mask:** modulate density (`accept if rng.float() < densityMask(field, p)`) and
  test biome/keep-out by **point evaluation only** — no gradient, no iteration. This is the
  PCG "sample surface → attribute-driven density/filter" separation. [V/I]
- **Floor/wall split + slope mask** comes free from `normal·up` (the air-positive field's
  outward normal, or the face normal). [I]
- **Blue-noise spacing on the surface** (pick by quality bar): (1) **spatial-hash
  dart-throwing** — accept a candidate only if no accepted neighbor within `radius`;
  variable-radius = variable-density; O(N) with the hash, deterministic given seeded candidate
  order (≈ Blender's Poisson-disk mode) — *start here*; (2) Mitchell best-candidate; (3)
  **Yuksel weighted sample elimination** — top-tier blue noise on arbitrary surfaces, weight
  encodes variable radius [V: Yuksel 2015] — promote to this only if the gate shows clumping.
- **Clustering** (optional): two-level — sparse blue-noise cluster centers, then children
  offset in the tangent plane and snapped to the nearest triangle. [K]
- **Per-instance variation:** seeded yaw about the normal, uniform scale jitter, variant pick.
  Embed slightly along `−normal` so items are seated, not floating. [K]

**Determinism discipline (the trap):** one `rng.derive("scatter:"+region+":"+layer)` per layer
(adding/removing a layer doesn't reshuffle others); draw variation RNG **only for accepted
points, in fixed field order**; back the spatial hash with **arrays/typed grids, not
`Map`/`Set`** (iteration order must not leak into the shuffle). sfc32 already guarantees
same-seed-same-sequence cross-machine. [I]

## 3. System architecture — rules / resolution / execution split (VALIDATED)

"theme declares scatter **layer specs** → shared `scatter()` → `RegionData.instances`
(resolved transforms) → `realize` via GPU instancing" is a faithful instance of the split
every production scatter system uses [V]:

- **Unreal PCG:** graph + settings (rules) → **points** with per-point attributes (resolved
  intermediate) → **Static Mesh Spawner** → HISM (execution).
- **Houdini:** scatter params → point cloud → copy-to-points → instanced geo.

`RegionData.instances` = PCG's "points" — payload `{pos, rot (quat), scale, variantId}` +
optional tint. Two refinements to bake in: (a) **group instances by variant** so `realize`
issues one instanced draw per variant geometry/material (HISM-style batching); (b) pass
keep-out / density-mask inputs **as data** (doorway AABBs, path polylines, optional field
handle) so `scatter()` stays a pure deterministic `(spec, surface, seed) → instances` function
— same posture as the `region.ts`/`compose.ts` unit-tested generators. [V/I]
