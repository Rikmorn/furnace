### packages/core (bullet as of the extraction)

- `packages/core/` (`@furnace/core`, private) — the engine library. Exposes its public surface as per-feature sub-path modules — `@furnace/core/{gpu, frame, geometry, mesh, material, camera, transform, post, events, stats, input, log, resources, physics, rigid-mesh, rng, scene}` — documented signature-by-signature in `docs/reference/core-modules.md` (concept taxonomy + naming rules in `docs/reference/api-posture.md`). Engine-wide conventions are committed at `docs/reference/engine-conventions.md`. **Browser-only**: no framework deps, no Bun coupling in core's source. The `tests/no-bun-leakage.test.ts` static scan is one guardrail; the full contract lives in "What we ship to consumers" below. Future wasm hot-path crates (transforms, audio) will live here. Contains no native binaries. (Slice 2.1.1 added `physics.castRay`/`castShape` query primitives — generic ray/shape-sweep probes consumers can build movement solvers on; both also return the hit body via `RayHit.body`. Slice 2.2.1 added the `voxels` `ShapeDescriptor` variant — a sparse, ghost-free static/kinematic voxel collider for field-derived level geometry, wrapping Rapier's voxel collider; heightfield was deliberately NOT added — it is broken in the vendored `rapier3d-compat@0.19.3` wasm.) **Slice 2.2.3a ("GPU instancing") added first-class instancing:** `mesh.createInstanced(ctx, { geometry, material, count })` → an `InstancedMesh` resource (own pool, dispose-cascade slot, `stats.resources.instancedMeshes` count) with per-instance setters `setInstanceTransform` (TRS) / `setInstanceTint` / `setInstanceMatrices` (bulk, column-major) / `setInstanceCount` (drawn prefix) / `destroyInstanced`; per-instance data rides a `stepMode:"instance"` vertex buffer (baked `mat4` at vertex-buffer slot 1, tint `vec4` at slot 2). Instanced shader variants `shader.litInstanced` / `shader.unlitInstanced` (+ `shader._instancedOf`) source the model matrix from those attributes, **bypass `@group(2)`**, and multiply a per-instance tint into the colour/albedo — **uniform per-instance scale only** (documented precondition: the lit variant derives the normal from `mat3(model)`). Instanced meshes are passed via a **separate** `instanced?: InstancedMesh[]` param on **both** `frame.render` (`RenderOptions`) and `renderToTexture` (`RenderToTextureOptions`) — deliberately **NOT** a `(Mesh|InstancedMesh)[]` union (overturned the spec's §3.5 union-list): `Mesh` and `InstancedMesh` handles collide numerically (both pools allocate from slot 1 → identical `encodeHandle(ctxId,1,1)`), so a runtime union can't soundly discriminate kind — the engine keeps drawable kinds in typed-distinct lists (its "kind known from typed slot, never inferred from a bare handle" invariant). Instanced groups draw after `meshes` in the same pass; emissive groups glow through the existing post chain. The per-instance-tint pixel-readback test also surfaced + fixed a pre-existing `renderToTexture` bug: RTT never called `_flushDirtyBindings`, so binding-set material uniforms rendered as their zero-initialised GPU value (black). Instanced meshes do **not** cast shadows yet (deferred — `docs/backlog/engine-architecture/shadow-follow-ons.md`, *Instanced meshes don't cast shadows* section); a bulk `setInstanceTints` to mirror `setInstanceMatrices` is deferred (`docs/backlog/engine-architecture/bulk-set-instance-tints.md`). Headless: `tests/gpu/instanced-mesh.gpu.test.ts` covers create/setters/draw + the per-instance-tint readback + the RTT flush fix. The `docs/backlog/engine-architecture/first-class-gpu-instancing.md` entry is resolved + deleted.)

The placer, `packages/dungeon/src/layout.ts` `layoutWorld(graph, seed)`, is a deterministic collision-aware incremental graph embedding in the Ma-2014/Edgar shape: pinned nodes seat first and stay frozen, then a most-constrained-first order (most already-placed neighbours first, ties broken by BFS depth from the pins, then id) places the rest one at a time by sampling candidate seatings — `join`-mating the node's portal to its already-placed parent portal at a seeded grid of connector lengths × yaw offsets (0°, ±15°, ±30°, ±45°) — hard-accepting the first candidate that clears the occupancy rules AND makes every now-both-placed edge (its own tree-seating edge, plus any loop-closing edges to already-placed neighbours) realizable via `route`, with bounded backtracking (a stack of revisable frames, a total-attempt cap) before throwing setup-loud with a per-node candidate-failure histogram. **Force-directed relaxation was research-overturned** as the placement foundation — no shipped system was found embedding a world graph by global force-directed relaxation; see `docs/research/2026-07-01-dungeon-2.2.5-layout-placement-and-megastructure.md` — in favour of this deterministic incremental embedder. Loop-closing edges never drive the candidate search that picks a node's position; they are only checked (and can trigger backtracking) once the tree edge has already placed the node. `layoutWorld` is pure: no GPU, no Rapier, no wall-clock. The collision model, `packages/dungeon/src/occupancy.ts`, tracks three obstacle classes — placed-piece **envelopes** (must never interpenetrate each other; exact touch is legal), placed-piece **solids** (conservative cuboid AABBs, or — for cave voxel proxies — exact per-cell membership, since the whole-grid AABB is mostly air and would false-reject any cave-mouth connector), and committed-connector **clearance volumes** (reserved walking air, segmented along a climb rather than one giant box) — checked pairwise across 5 acceptance rules (piece-vs-piece envelopes; piece envelopes vs. committed clearance air; clearance air vs. piece solids outside a **portal exemption** — a box around each portal a connector is allowed to bore through its own endpoints' walls near the seam, so only deeper clips reject; clearance air vs. a non-endpoint piece's envelope; and clearance air vs. another committed connector's air or its floor slab). `connect.ts route` was hardened for the new direction-agnostic caller: descending stair-runs now emit a real mirrored staircase instead of a `dh<0` empty step loop, and the ramp slope-limit guard now tests `Math.abs(pitch)` so a forced steep DESCENDING ramp throws setup-loud like its ascending counterpart — resolving the carried `connect-route-descending-stairs-empty` backlog. `themes/box-room.ts` generalizes `BoxRoomParams.door` (one `DoorSpec`) to `doors: DoorSpec[]` (≥1, at most one per cardinal side, setup-loud on violation) so rooms of degree > 1 exist for a graph world; `pillarHall` exposes this as an optional param (default = the historical single S door), `greatHall` stays single-door.
