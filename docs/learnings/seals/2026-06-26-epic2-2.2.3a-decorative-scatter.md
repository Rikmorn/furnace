**Epic 2 · Slice 2.2.3a ("Decorative scatter") then landed (2026-06-26):** a pure, deterministic decorative scatter system that dresses the generated regions with GPU-instanced props (consuming core's new instancing — see the `packages/core` bullet). `packages/dungeon/src/scatter.ts` area-weight-samples the generated Surface-Nets mesh (`meshSurface` + `_sampleSurface` — triangle-area CDF + barycentric √-debias) — with a flat-floor `rectSurface` adapter for box rooms — then `scatter()` applies slope/density/keep-out **masks** + blue-noise **dart-throwing** spacing + per-instance variation (scale/rotation/tint jitter) + surface-aligned **orientation** (`_orient`, incl. ceiling-hang anchoring so ceiling items dangle *into* the room); `instanceGroupsFromLayers` bakes the results into GPU-ready `InstanceGroup`s (column-major transforms, grouped by archetype variant, materials deduped). The region contract gains a `RegionData.instances: InstanceGroup[]` seam fed by theme-declared `ScatterLayerSpec` layers (each a `MaterialPosture` `lit` | `emissive`); `realize.ts` does posture-aware instanced realization (`lit` → `litInstanced`, `emissive` → `unlitInstanced` + bloom — **emissive scatter is purely visual glow, NOT real light**: real scattered lights stay deferred behind the 16-light forward cap → `docs/backlog/engine-architecture/many-lights-clustered-or-deferred-shading.md`); `main.ts` renders the groups via `frame.render({ instanced })`. Content: a **5-layer cave showcase** (rubble + crystal-spires `lit`; glow-fungus + wall-crystals + glow-worms `emissive` — spanning floor / wall / ceiling, the ceiling glow-worms hanging down) plus a lean box-room floor scatter. **Coordinate frames:** the cave bakes **world** transforms (local scatter offset by the region origin) while rooms bake **local** transforms that `compose.ts placeRoom` transforms into world. Archetypes are **uniform-scaled unit primitives** (cube / sphere / cylinder) — real procedural archetype meshes (the worm/spire silhouette) are deferred (`docs/backlog/dungeon/visual-polish-pass.md`, *real procedural archetype meshes for decorative scatter* section). Decoration is **non-colliding** — collision + walking are unchanged. No `@furnace/core` change beyond the consumed instancing. Headless: `tests/scatter.test.ts` unit-tests the sampling/mask/spacing/orient math (deterministic), `tests/scatter-realize.gpu.test.ts` covers the realize→GPU path; scatter feel stays a visual gate (passed Safari/Chrome).
