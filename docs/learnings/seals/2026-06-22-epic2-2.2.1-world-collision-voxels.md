# Epic 2 · Slice 2.2.1 — "World collision via field-derived voxels"

- **Sealed:** 2026-06-22
- **Package(s):** core, dungeon
- **Gate:** three gate rounds; traversal feel passed Safari/Chrome
- **Suite:** not recorded

**Epic 2 · Slice 2.2.1 ("World collision via field-derived voxels") then landed (2026-06-22):** the three generated regions (cavern, shaft, chamber) now collide against ghost-free **field-derived Rapier voxel colliders** instead of the internal-edge-prone render trimesh — killing the curved-wall-stuck / floor-stall / hall↔chamber fall-through bug class at the root (the same internal-edge ghost collisions the 2.1.1 controller works *around*, now removed from the collision representation itself). Core gained one thin static shape — the `voxels` `ShapeDescriptor` variant (`{ coords: Int32Array; size }`, signed int grid coords 3-per-voxel, wrapping `RAPIER.ColliderDesc.voxels`; **heightfield was excluded — broken in the vendored 0.19.3 wasm**). The dungeon adds `packages/dungeon/src/proxy.ts` (`voxelsFromField` sign-samples each grid cell centre → solid-cell coords, shell-only drops fully-enclosed interior cells; `voxelProxyPosition` seats the proxy body — Rapier voxels are corner-anchored, so `HALF_VOXEL = 0` aligns voxel cell (i,j,k) with its field/render cell) plus a generator `generateProxy` (field-only, no Surface-Nets) so each region carries a `proxy` + `proxyPosition` alongside its `mesh`. The shaft + chamber collide against `region.proxy`; the **cavern is now render-only** (its scene dropped `rigidBody`) with a voxel proxy regenerated at runtime from the same seed/kind/origin as the baked mesh (deterministic → matches). Authored `LEVEL_BOXES` stay `cuboid`; dynamic props stay Rapier dynamic bodies; the `CharacterMover` is **unchanged** (it casts against colliders uniformly, never distinguishing voxel from cuboid). The chamber grid's +Z footprint was widened (dims.z 12→14) to **overlap** the authored corridor floor, closing the hall↔chamber seam by coverage. The accepted tradeoff is voxel blockiness, absorbed by the 2.1.1 camera eye-height smoothing plus **anisotropic-Y voxels** — `buildProxy` voxelizes at `voxelSize=[cellSize, 0.25, cellSize]` (`PROXY_VOXEL_Y=0.25`), so a floor-height quantization step is 0.25 m (< the controller's 0.4 m `STEP_HEIGHT`) instead of a stalling 0.5 m cubic cell. Three gate rounds hardened it: `voxelsFromField` treats **off-grid neighbours as solid rock** in the shell-only enclosure test (a grid-boundary rock cell is kept only if it borders *in-grid* air → the collision shell follows the rendered isosurface, not the grid box → kills an invisible grid-boundary collision wall); the cavern field is a `boxCavern` sized to its authored square pit (no rim poking up through the chamber floor; `.fmesh` re-baked to match); and `char-move.ts applyGravity` takes its rest height from a downward capsule **shapecast** (rim-riding — rests on the highest support in the footprint instead of a single ray sinking the capsule into a sub-capsule voxel pocket). Headless: the core `voxels` shape (ray/shapecast + ball-rest), the CharacterMover-traverses-voxels (chamber walk + shaft drop), the seam-coverage probe, and a `traversal.gpu.test.ts` fuzz harness (every lane walks the full chamber, no wedge, no fall-through) are `.gpu.test.ts`-covered; `voxelsFromField`/`voxelProxyPosition` are unit-tested; traversal feel stays a visual gate (passed Safari/Chrome). The core `trimesh` shape + the scene-loader trimesh-collision path (`retainForCollision`/`getCollisionData`/scene `rigidBody.shape.trimesh`) are **kept** (tested public API; scene-baked collision belongs to 2.3 recipe-as-truth). The forward direction (voxels are a confirmed *bridge*; endgame = collide the render mesh on Jolt's `CharacterVirtual`) lives in `docs/backlog/engine-architecture/jolt-backend-swap.md` + `docs/learnings/jolt-mesh-collision-spike.md`.
