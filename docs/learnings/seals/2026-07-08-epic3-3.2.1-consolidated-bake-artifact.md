# Epic 3 · Slice 3.2.1 — Consolidated bake artifact

- **Sealed:** 2026-07-08
- **Package(s):** dungeon, editor
- **Gate:** user-gated Safari
- **Suite:** 1309 pass / 1 skip / 0 fail

**Epic 3 · Slice 3.2.1 ("Consolidated bake artifact") landed (2026-07-08, user-gated Safari):** the wing bake collapsed from ~27 files (one render-only `.scene.json` per node + per connector) to ~7 — ONE merged `wing.scene.json` + `manifest.json` + `.fmesh` sidecars, under a nameable `regions/<name>/`. Dungeon side: `bake.ts`'s per-piece `regionDoc` factory became an `appendPiece(mergedDoc, dir, id, region)` accumulator that folds EVERY placed piece — regions AND connectors (erasing the 3.1 per-connector-doc spec deviation rather than patching it) — into one `SceneDocument`; entity ids were already piece-prefixed (`<id>-m<mi>`), and this slice piece-prefixes the RESOURCE keys too (`<id>-m<i>` materials, `<id>-g_mesh_<mi>` custom geometries) so merged pieces can't collide, with `g_cube`/`s_lit` kept as shared singletons. `WingManifest` dropped per-entry `file` (regions AND connectors) and gained a top-level `scene` path; `version` stays `1` (D6 — only current dungeon code consumes it, no version machinery). **The manifest-last crash-safety invariant was promoted from accident to a TESTED contract:** `manifest.json` is the last element of the returned `files` array and the daemon's write loop is sequential in array order, so an interrupted bake leaves no manifest → `loadGeneratedWing` falls back to live generation → a torn wing never loads. `bakeWing` gained a 4th `name = "generated-wing"` param (setup-loud `WING_NAME_RE = /^[a-z0-9][a-z0-9_-]*$/i`) → `regions/<name>/` via the new `wingDir(name)` (D7); `WING_DIR` kept as the compat default. `wing-loader.ts` now does ONE `fetchArtifact(manifest.scene)` + ONE fragment `loadScene` (replacing the ~26-doc loop) plus per-piece cuboid static bodies via the extracted `createColliderBodies`, and gained a stale-bake guard (`manifest.scene` missing → throw "…re-bake", D6); the cave voxel-proxy + dressing re-expansion are unchanged except the dressing's `.fmesh` base dir now derives from `manifest.scene` rather than a hardcoded `WING_DIR`. **Placement-LEVEL parity (`bake-dressing-parity.test.ts`) stayed intact and unmodified** (the 3.1 lesson: count-level assertions lie). Editor side: the daemon's `generation.bake` gained an optional, validated `cleanDir` — root-contained (never the root itself), no dotfile segments, AND every payload file must live under it (setup-loud against wiping one dir while writing another); order is validate-everything → `rm -rf cleanDir` → write (write loop untouched, manifest last) — so a smaller re-bake leaves no orphans and a mismatched payload leaves the FS untouched. The Generation panel gained a wing-name field (independent state — a bake DESTINATION, so it does NOT invalidate a `done` preview) gating Freeze on a UI-boundary `isValidWingName` mirror of the bake regex; freeze threads `ext.bake(seed, config, budget, wingName)` + `api.generationBake(files, ext.wingDir(wingName))` (cleanDir). `editor-extensions.ts` re-exports `DEFAULT_WING_NAME`/`wingDir`/4-arg `bake` through the cockpit seam. **Execution notes:** Tasks 2+3 landed as ONE atomic commit — dropping `file` from `WingManifest` breaks the loader at both typecheck and the `wing-roundtrip.gpu.test.ts` runtime (bun-webgpu runs the real loader), so bake-format and loader are coupled by the type ([[feedback_cross_package_type_changes_atomic]]). Surfaced-not-silently-changed: the spec-pinned wing-name regex is case-insensitive (so `My-Wing`/`my-wing` collide on case-insensitive FS) and permits Windows reserved device names — noted, regex unchanged (it is the contract, mirrored in 3 places). The naming feature exposed that `.gitignore`/`biome.json` ignore only the DEFAULT `regions/generated-wing/` (the rest of `regions/` holds committed `region-cavern.*` fixtures) — a non-default wing lands un-ignored; deferred with the named-wing wiring to `docs/backlog/dungeon/worlds-index-manifest.md` (D7 — the game loader still reads only the well-known default; a dungeon-level worlds index is packaging-time work). Gate: user baked → ONE `wing.scene.json` + manifest + 3 `.fmesh`, no orphans, walked identical feel. Suite 1309 pass / 1 skip / 0 fail; typecheck + check clean. **No `@furnace/core` change.**
