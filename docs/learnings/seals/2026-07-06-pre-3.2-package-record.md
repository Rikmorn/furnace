### packages/core (bullet as of the extraction)

- `packages/core/` (`@furnace/core`, private) — the engine library. Exposes its public surface as per-feature sub-path modules — `@furnace/core/{gpu, frame, geometry, mesh, material, camera, transform, post, events, stats, input, log, resources, physics, rigid-mesh, rng, scene}` — documented signature-by-signature in `docs/reference/core-modules.md` (concept taxonomy + naming rules in `docs/reference/api-posture.md`). Engine-wide conventions are committed at `docs/reference/engine-conventions.md`. **Browser-only**: no framework deps, no Bun coupling in core's source. The `tests/no-bun-leakage.test.ts` static scan is one guardrail; the full contract lives in "What we ship to consumers" below. Future wasm hot-path crates (transforms, audio) will live here. Contains no native binaries. (Slice 2.1.1 added `physics.castRay`/`castShape` query primitives — generic ray/shape-sweep probes consumers can build movement solvers on; both also return the hit body via `RayHit.body`. Slice 2.2.1 added the `voxels` `ShapeDescriptor` variant — a sparse, ghost-free static/kinematic voxel collider for field-derived level geometry, wrapping Rapier's voxel collider; heightfield was deliberately NOT added — it is broken in the vendored `rapier3d-compat@0.19.3` wasm.) **Slice 2.2.3a ("GPU instancing") added first-class instancing:** `mesh.createInstanced(ctx, { geometry, material, count })` → an `InstancedMesh` resource (own pool, dispose-cascade slot, `stats.resources.instancedMeshes` count) with per-instance setters `setInstanceTransform` (TRS) / `setInstanceTint` / `setInstanceMatrices` (bulk, column-major) / `setInstanceCount` (drawn prefix) / `destroyInstanced`; per-instance data rides a `stepMode:"instance"` vertex buffer (baked `mat4` at vertex-buffer slot 1, tint `vec4` at slot 2). Instanced shader variants `shader.litInstanced` / `shader.unlitInstanced` (+ `shader._instancedOf`) source the model matrix from those attributes, **bypass `@group(2)`**, and multiply a per-instance tint into the colour/albedo — **uniform per-instance scale only** (documented precondition: the lit variant derives the normal from `mat3(model)`). Instanced meshes are passed via a **separate** `instanced?: InstancedMesh[]` param on **both** `frame.render` (`RenderOptions`) and `renderToTexture` (`RenderToTextureOptions`) — deliberately **NOT** a `(Mesh|InstancedMesh)[]` union (overturned the spec's §3.5 union-list): `Mesh` and `InstancedMesh` handles collide numerically (both pools allocate from slot 1 → identical `encodeHandle(ctxId,1,1)`), so a runtime union can't soundly discriminate kind — the engine keeps drawable kinds in typed-distinct lists (its "kind known from typed slot, never inferred from a bare handle" invariant). Instanced groups draw after `meshes` in the same pass; emissive groups glow through the existing post chain. The per-instance-tint pixel-readback test also surfaced + fixed a pre-existing `renderToTexture` bug: RTT never called `_flushDirtyBindings`, so binding-set material uniforms rendered as their zero-initialised GPU value (black). Instanced meshes do **not** cast shadows yet (deferred — `docs/backlog/engine-architecture/shadow-follow-ons.md`, *Instanced meshes don't cast shadows* section); a bulk `setInstanceTints` to mirror `setInstanceMatrices` is deferred (`docs/backlog/engine-architecture/bulk-set-instance-tints.md`). Headless: `tests/gpu/instanced-mesh.gpu.test.ts` covers create/setters/draw + the per-instance-tint readback + the RTT flush fix. The `docs/backlog/engine-architecture/first-class-gpu-instancing.md` entry is resolved + deleted.)

### packages/dungeon (bullet as of the extraction)

- `packages/dungeon/` (`@furnace/dungeon`, private) — the first-person dungeon-crawler demo (the retargeted go-forward app — see `~/.claude/.../memory/project_dungeon_crawler_vision.md`). Browser-first consumer; imports core via the workspace symlink; owns its own `index.html` + `serve.ts`; run `bun run dungeon:dev`. **Epic 1 ("Presence & Mood") landed:** a hand-authored corridor→cave level on lit box primitives, a pointer-lock FP controller (raw DOM `movementX/Y` — `@furnace/core/input` has no relative-pointer mechanism; deferred to backlog), a carried flickering torch (point light follows the player), distant unlit-bloom glows over an HDR `bloom→tonemap` post chain, exponential distance **fog** (the one `@furnace/core` mechanism this epic added — `@furnace/core/frame` `Fog`), and optional additive drifting motes.

### packages/editor (bullet as of the extraction)

- `packages/editor/` (`@furnace/editor`, private) — the editor (M4 command layer + M5A inspector + M5B viewport interaction landed). A Node-portable daemon (no `Bun.*` in `src/`, enforced by `tests/no-bun-leakage.test.ts`) that serves the editor frontend same-origin and owns a zod-validated command registry over `POST /api/<command>`: a mutable document session (open/save, transactional registry-validated mutations, snapshot undo/redo), an SSE change feed (`GET /api/events`), and scene-file watching with conflict semantics. It esbuild-bundles the consumer's `@furnace/core` + extensions twice — a browser engine bundle and a node-platform registry bundle for daemon-side validation (project-first resolution — the editor contains no engine). React 19 + dockview chrome (prebuilt to `dist/frontend`, served by the daemon); dogfood: `bun run edit` in `packages/hello-world`. M5A added an editable, reflection-driven inspector (component + settings + resource editing with live preview), multi-entity selection (replace/toggle/range, modifier-click), and the `scene.batch` command (atomic multi-entity edit, one undo entry). M5B added GPU-id viewport picking, AABB selection highlight, a translate gizmo (3-axis drag, anchor-relative-absolute, multi-select one-undo), an editor orbit/pan/zoom camera (init from scene cam, never serialized), NumberField drag-scrub (Safari-safe Pointer Events, Shift=fine), focused-input echo-guard, and `revertSettings`. The consumer's `@furnace/core` scene loader (which the editor renders, owning no engine itself) now instantiates the **full built-in set** from data — geometry cube/sphere/cylinder/plane, shaders unlit/lit/texturedLit/textured/normalColor, textures checkerboard/load, standard material (+texture/sampler), effects bloom/tonemap, light directional/point/spot, rigidBody static/dynamic — plus **physics-from-data** (lazy world + rigidMesh composite, instantiated but **NOT stepped** — a consumer's game loop drives stepping). The editor viewport renders scene lights+ambient (the lit-viewport payoff) and defers the post chain (`effects: []`, non-HDR context — fidelity, not a crash). AI bindings (MCP mount, viewport capture, embedded/outbound LLM) are deferred to `docs/backlog/editor-and-tooling/editor-ai-integration-milestone.md`. **Slice 3.0** added a daemon inner-loop watch: it now watches the consumer's extensions directory and emits a `bundle-outdated` SSE event so the browser reloads on source change (closing the cockpit inner-loop's browser-engine-bundle staleness gap), and the dungeon is editor-openable (`bun run edit` in `packages/dungeon`). **Slice 3.1 ("the Loop")** added the generation cockpit: an engine-bundle-side **preview host** (`createPreviewHost` — HDR+fog+orbit, generation-session-only), the browser bundle's `extensions`-namespace generator seam, a dockview **Generation panel** + ephemeral session (stepped `worldAttempts` preview → reroll → freeze&bake), the **`generation.bake`** command, camera-less **fragment-doc opening** in the viewport host, and session concurrent-open race hardening + registry `invalidate()` on the extensions-dir watch. The bake uses the **browser-uploads-payload** fallback — the browser bakes the wing in its own engine and uploads the file set, the daemon just validates+writes+emits `generation-baked` — adopted because a Pr-2 probe found world placement diverges bun/JSC vs node/V8 (`docs/learnings/2026-07-06-cross-engine-placement-determinism.md`). Gate hardening (found live, 2026-07-06): both viewport canvases stay LAID OUT at all times (visibility swap, never `display:none` — a zero-size canvas throws in `bindToCanvas` at host init); **fog is a viewport VIEW-FLAG** (`PreviewHost.setFog`, default OFF — game-density fog at orbit distance obscures the structure the cockpit exists to show; the toggle lives on the viewport overlay, the UE/Unity show-flags pattern, seed of 3.2's view-flags block); freeze reads only the `done`-status config SNAPSHOT (knob edits invalidate the preview — freeze bakes exactly what is on screen). Gate-found cockpit UX gaps + the DECIDED single-`wing.scene.json` bake consolidation are 3.2 inputs: `docs/backlog/editor-and-tooling/generation-cockpit-ux-gate-findings.md`. Architecture: `docs/reference/editor-architecture.md`.
