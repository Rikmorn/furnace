**Epic 3 · Slice 3.2.3 ("cockpit hardening") landed (2026-07-10, user-gated Safari):** the Generate button became honest and cheap-to-fail — **no `@furnace/core` change** (dungeon + editor only). Executed via superpowers:subagent-driven-development (14 tasks, fresh implementer + two-stage spec/quality review each; 10 commits off `24eeaa5`). **Dungeon:** `LayoutBudget.deadlineMs` — a SEARCH-TIME wall-clock ceiling for one `layoutWorld` call, default `Infinity` (byte-identical defaults); greedy/placement sites gate on `searchExpired` (counted OR deadline) while the SA-fallback loops gate on deadline-only `deadlineExpired` — **the review caught that gating SA on the counted budget starves the rescue that fires precisely after greedy exhausts** (a real pass→throw regression in the plan's literal code, fixed with a fails-before/passes-after test); the deadline throw is distinct (`layout: deadline <n>ms exceeded…`) so give-up diagnostics separate grind-kill from search exhaustion. **D4 determinism invariant (TESTED):** `bakeWing` strips `deadlineMs` (forces `Infinity`) — a deadline is machine-speed-dependent and can only PREVENT successes, never create them, so the bake replay of a previewed winner is counted-only deterministic. **The Task-0 re-probe ran BEFORE any number was committed** (`measure-b2c.ts --envelope [rooms|-] [loop|-] [deadlineMs]`, cells sequential): chosen deadline **2000 ms** (no cell dropped >10pp vs the no-deadline baseline; successes survive — succ_p95 <900 ms; failures bounded ~2.3–2.7 s vs the old 20–105 s grind); the full 2–12 sweep committed VERBATIM as **`COCKPIT_ENVELOPE`** (one row per knob value: singleShot/attempts/projected, e.g. 6→0.35/7/0.951, 10→0.10/24/0.920, **12→0.05/23/0.693 — measured low-yield, recorded honestly per the spec's stop condition, not tuned away**; the 7<8 rate inversion is 1-seed sampling noise, kept); per-row attempts = ~95%-target, floor 4, capped by ~60 s worst-case ÷ **measured give-up p95** (review fixed the cap divisor from the nominal deadline — committed counts now honor the bound in reality); `COCKPIT_BUDGET.deadlineMs = 2000`. **Editor:** generation moved off the main thread — a module Web Worker (`/generation-worker.js`, its own Bun.build entry) imports the SAME same-origin `/engine.js` the chrome loads (same JS engine, so the Pr-2 cross-engine placement rule is not in play); a runId-disciplined protocol (`generation-protocol.ts`) with a PURE `createWorkerHandler` factory (unit-tested with no real Worker: transfer-list dedupe for aliased typed-array buffers, every failure path posts a typed message, `wantSuccesses` MUST be 1 — setup-loud, reserved for 3.2.5's contact sheet); an App-owned `GenerationWorkerClient` — **cancel = `terminate()` + lazy respawn: instant, mid-attempt, no cooperation from the search** — plus a worker-identity guard (review caught a queued init-error from a terminated worker misattributing to a new run's handler); **the paint-gap stepper was DELETED, no silent fallback** (worker spawn/import failure is a setup-loud `failed` status). Panel: knobs clamp at commit to the measured envelope (rooms→table range, loop→[0,0.6] snapped) with a visible note — out-of-envelope is refused at the UI boundary, never fail-slow-searched; a measured reliability line under the Rooms knob (low-yield sizes say so); the failed status carries the LAST attempt error (deadline vs exhaustion visible); realize stays main-thread and runs once on the winner; freeze's bake runs in-worker (daemon upload unchanged). **bundle-outdated stance (conscious deviation from the spec):** the worker is NEVER respawned alone — that would version-split worker-side generation from main-thread realize/bake; a page reload refreshes both together. Adjacent finding carried forward: the envelope covers only the current single-sector config — bigger configs (multi-sector) need their own measurement pass (noted in the pruned gate-findings entry).
